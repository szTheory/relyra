## Cross-Phase Integration Findings

### Blockers

**INT-01 — XMLEnc.decrypt/3 → ValidationPipeline: decrypt step absent** *(ENC-01)*

`Relyra.Security.XMLEnc.decrypt/3` exists at `lib/relyra/security/xml_enc.ex` but is called by nothing in `lib/`. `ValidationPipeline.@ordered_stages` has no `:decrypt_assertion` step. An encrypted assertion response entering `do_run_validations/6` bypasses decryption entirely — the CVE-2025-54419 decrypt-then-reparse-then-verify invariant is not active in any live code path. Phase 34 must add the `:decrypt_assertion` step and wire it into the pipeline.

**INT-02 — AlgorithmPolicy.signing_digest_atom/1 missing** *(AUTHN-01, AUTHN-03)*

STATE.md notes Phase 35 "needs `AlgorithmPolicy.signing_digest_atom/1`" from Phase 32. The function does not exist anywhere in `lib/` (zero grep results). Phase 32 PLAN.md did not scope it. Phase 35 has two resolution paths:

- **(Recommended)** Use existing `digest_atom_for_signature_method/1` directly for the RSA-SHA256 case in `sign_redirect_query/3` — avoids retrofitting Phase 32 and the function already maps `rsa-sha256` URIs to `:sha256`.
- Alternatively, add `signing_digest_atom/1` to `AlgorithmPolicy` as Phase 35 Plan 01 Task 0.

### Warnings

**WARN-01 — SP metadata publishes no KeyDescriptor elements** *(ENC-02, AUTHN-03)*

`Protocol.Metadata.build_sp_metadata/2` emits only `<md:AssertionConsumerService>` — no `<md:KeyDescriptor use="encryption">` and no `<md:KeyDescriptor use="signing">`. The live metadata endpoint serves this incomplete metadata to IdPs today. Both Phase 34 (ENC-02) and Phase 35 (AUTHN-03) must extend `build_sp_metadata/2`.

**WARN-02 — Certificate.party/use fields have no runtime consumers** *(ENC-04 partial, ENC-02)*

`Certificate.party` and `Certificate.use` exist in the Ecto schema and changeset but no runtime code in `lib/` filters certificates by these fields. Phase 34 must add a certificate query by `party: :sp, use: :encryption` when building the encryption `KeyDescriptor`.

**WARN-03 — XMLEnc.resolve_key/2 bypasses Relyra.KeyResolver dispatch** *(ENC-04)*

`XMLEnc.resolve_key/2` calls `apply(key_resolver_module, :resolve, [connection])` directly (arity-1) rather than via `Relyra.KeyResolver.resolve/2`. A caller passing `Relyra.KeyResolver` itself (arity-2) instead of an adapter would fail silently to `:decryption_failed`. Phase 34 API surface documentation must clarify the adapter contract.

**WARN-04 — Binding.encode_redirect/3 missing DEFLATE compression** *(AUTHN-01 pre-condition)*

`Binding.encode_redirect/3` base64-encodes the SAMLRequest directly without DEFLATE compression, contrary to SAML 2.0 HTTP-Redirect Binding spec §3.4.4.1. Confirmed by conformance test line 71. This becomes load-bearing for Phase 35's AUTHN-01 golden corpus — the golden fixture output will differ depending on whether DEFLATE is fixed. Phase 35 must resolve this.
