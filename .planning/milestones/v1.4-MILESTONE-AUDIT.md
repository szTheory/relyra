## Critical Findings

### BLOCKER 1 — `guides/recipes/logout.md` SessionAdapter signature drift

**Affected requirements:** DOCS-04, SLO-01

**Location:** `guides/recipes/logout.md:107` and `:121`

**Problem:** The example shows:

```elixir
def index_session(connection, login_result, local_session_id, opts), do: ...
def terminate_by_session_index(connection, session_index, _name_id, opts), do: ...
```

Actual callbacks in `lib/relyra/session_adapter.ex:19-31`:

```elixir
@callback index_session(session_index, issuer, context, opts) :: ...
@callback terminate_by_session_index(session_index, issuer, context, opts) :: ...
```

A host implementing the example as written will fail `@behaviour Relyra.SessionAdapter` checks at compile time. This is the headline operator guide for the milestone's headline feature — it has to be right.

**Recommended fix:** Rewrite both code blocks to match the real signature. Re-verify against the live module. Add a passing doc test (or at least a `rg` assertion in `ci.docs`) that pins the example's argument count to the callback's arity.

### WARNING 2 — `SessionAdapter.index_session/4` has no in-tree caller

**Affected requirements:** SLO-01

**Location:** `lib/relyra.ex:363-382` (`consume_response/3`)

**Problem:** `consume_response/3` extracts `session_index` into the returned `Principal` but never registers it with `SessionAdapter.index_session/4`. Because nothing in `lib/` invokes the callback, an IdP-initiated SLO arriving later has no in-tree path from `SessionIndex` → local session — the host application must hand-roll that mapping with no facade hook.

This is either:
- (a) **Intentional** — Relyra delegates session-index registration to the host (consistent with the broader "host owns sessions" stance). If so, it needs an explicit one-line operator note in `logout.md` ("you must call `MyAdapter.index_session/4` from your ACS controller when storing the session"), or
- (b) **A wiring gap** — `consume_response/3` was meant to auto-register and didn't.

Recommended fix: pick (a) or (b) deliberately and document/wire accordingly.

### WARNING 3 — `38-04-SUMMARY.md` API name drift (non-blocking)

**Affected requirements:** none (cosmetic)

**Problem:** SUMMARY claims `Relyra.consume_logout_response/3`. Actual export is `Relyra.consume_logout/3` (request/response auto-detect). Code/tests use the correct name. Summary nomenclature is misleading for anyone reading the planning trail.

Recommended fix: edit `38-04-SUMMARY.md` to say `consume_logout/3`.
