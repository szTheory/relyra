# Roadmap: Relyra v1.1

## Milestone

**v1.1 — Verify the Trust Path**  
Shipped 2026-05-25.

## Scope

This milestone closed a published SAML authentication bypass by replacing structure-only signature acceptance with real XMLDSig verification, proving the canonicalization path against an independent oracle, permanently gating adversarial crypto regressions in CI, and staging the disclosure artifacts for ship time.

Requirements:
- `SIGV-01`
- `SIGV-02`
- `SIGV-03`
- `SIGV-04`
- `ASSUR-01`
- `ASSUR-02`
- `DISC-01`
- `DISC-02`

## Phases

- [x] **Phase 28: Real C14N parser foundation** — Replaced regex string-scanning with a real `saxy` parse tree, added a pure-BEAM exclusive-C14N engine, and proved byte-exact canonicalization against committed oracle fixtures.
- [x] **Phase 29: Cryptographic XMLDSig verification** — Wired real `:public_key.verify` and `DigestValue` recompute/compare into both response/assertion and metadata-root verification paths.
- [x] **Phase 30: Adversarial crypto assurance** — Promoted FakeIdP to real XMLDSig signing, added the permanent adversarial crypto corpus, and fixed a latent hollow `ci.security` gate so the security lane genuinely gates every build.
- [x] **Phase 31: Disclosure and docs honesty** — Corrected reviewer/security docs, recorded `RELYRA-2026-001` in the findings ledger, and staged the GHSA/CVE/release-note advisory draft.

## Phase Details

### Phase 28: Real C14N parser foundation
**Goal**: Verification can operate over a correct, canonicalized parse tree — the precondition for any cryptographic check.  
**Depends on**: Nothing new (extends the existing `Relyra.Security.XML` seam shipped in v0.1).  
**Requirements**: `SIGV-03`  
**Plans**: 4/4 complete

### Phase 29: Cryptographic XMLDSig verification
**Goal**: A forged or tampered SAML signature is cryptographically rejected; only a genuinely-signed node from the configured IdP verifies.  
**Depends on**: Phase 28.  
**Requirements**: `SIGV-01`, `SIGV-02`, `SIGV-04`  
**Plans**: 5/5 complete

### Phase 30: Adversarial crypto assurance
**Goal**: The proof that verification is real lives permanently in-repo and gates every build.  
**Depends on**: Phase 29.  
**Requirements**: `ASSUR-01`, `ASSUR-02`  
**Plans**: 4/4 complete

### Phase 31: Disclosure and docs honesty
**Goal**: The shipped story matches the code, and a coordinated advisory is staged for the fixed release.  
**Depends on**: Phase 30.  
**Requirements**: `DISC-01`, `DISC-02`  
**Plans**: 2/2 complete
