# v1.12 — Trust-Path Hardening (evidence)

One evidence file for the whole milestone (no new receipt chains). It records the
confirmed seam inventory with fixed-in commits, the generative-testing rounds,
the mutation-score trend, and the residual risk.

**Milestone branch:** `docs/v1.12-start`, merged as PR #62 (`a95f6e7`).
**Release:** Hex `1.10.2`, tag `v1.10.2` at `ab19bc0` (release PR #63).
**Base:** `main` at `relyra 1.10.1`.

## What this milestone is

While researching the v1.12 "Adversarial Twin" we confirmed an authentication
bypass in `Relyra.consume_response/3`: the XMLDSig signature verified (the
`1.2.0` fix from RELYRA-2026-001 holds), but the *consumed* identity, condition,
and attribute fields were taken from a root-wide search rather than from the
single signed `<Assertion>`. An attacker could add a `NameID`, `Conditions`, or
`AttributeStatement` **outside** the signed assertion and have it consumed while
the signature still verified. A seam audit found the same verified-node ≠
consumed-node gap across the logout, redirect, encrypted, and metadata paths.

The milestone fixes every seam in the open ("fail forward"), then hammers the
core with property-based and mutation testing to diminishing returns, and closes
with a scripted advisory.

### Phase 80 — login trust path (commit `2782344`, closeout `e6da2bd`)

| Seam | What it was | Fix |
|------|-------------|-----|
| **S1** | `DigestValue`/`SignedInfo`/`SignatureValue`/`Transforms` found anywhere inside `<Signature>` | crypto inputs read only from the bound Signature's direct children |
| **S2** | `Reference` URI never checked against the candidate ID; Reference count unchecked | exactly one Reference, `URI == "#" <> Assertion@ID` |
| S3 | signature not required to be the enveloped direct child of the Assertion | enveloped direct-child `ds:Signature` enforced; enveloped prune removes the bound node by identity |
| S4 | `SignatureMethod`/`DigestMethod` read document-wide; `CanonicalizationMethod` ignored | methods read from the bound `SignedInfo`; digest uses the bound `DigestMethod`; exc-c14n allow-listed |
| **S6/S7** | `bind_signed_node/2` a no-op; every assertion field from root-wide search (the confirmed bypass) | every field derived by structural path from the bound Assertion only; `consumed_xml_id == signed xml_id` enforced |
| S8 | ID-less decoy assertion still fed the fields | exactly one direct-child `saml:Assertion`, else `:ambiguous_signed_node` |
| S9 | `SubjectConfirmationData@InResponseTo` / bearer `Method` never checked | bearer SCD + `InResponseTo` enforced |
| S10 | only the first `Issuer`/`StatusCode` anywhere checked | Assertion `Issuer` + top-level `Status` only; `:assertion_issuer_mismatch` |
| S11 | root never required to be `samlp:Response` | `:unexpected_root_element` |
| S20 | elements matched by local name only, ignoring namespace URI | namespace-URI-aware matching |

## Phase 82 — property-based adversarial twin (commit `ad6ad64`)

A generative twin genuinely signs Response / enveloped LogoutRequest / redirect
query / `EntityDescriptor` documents, mutates them (sign-then-mutate and
mutate-then-resign) across every mutation family, and drives them through the
real public APIs. The oracle accepts `{:ok}` only when the consumed identity
equals exactly what the generator **signed**, else requires an allow-listed typed
rejection; a raise/exit/timeout/heap blow-up is a defect.

**Round log:**

| Round | Scope | Cases | New defect class |
|-------|-------|-------|------------------|
| 1 (dry, OTP 28) | all four kinds | ~4,800 | none (code); 2 oracle-model corrections |
| seeded lane (OTP 28) | all four kinds | 120–240/property | none |
| 2 (CI OTP 27 / 1500 runs) | all four kinds | ≥1,500/property | **1 real defect → fixed** |

The two round-1 triage items were **oracle-model corrections, not code
changes**: (a) `Metadata.Parser.parse/2` is a structural extractor, not a
signature verifier (that is `Signature.verify_metadata_root`, whose crypto core
the logout_post twin fuzzes) — the metadata generator was retargeted to its real
contract, authoritative-node selection; (b) three algorithm-policy error atoms
(`:deprecated_algorithm`, `:legacy_algorithm_override_expired`,
`:unknown_signing_algorithm`) were added to the oracle's allow-list.

**Round 2 found a real defect** that local OTP-28 runs had missed and the PR's
OTP-27 CI lane surfaced (it is seed-dependent, not OTP-specific): a truncated
prolog processing instruction (e.g. `"<?t"`) made **Saxy itself raise** a
`CaseClauseError` inside `prolog_pi_content/7`, so the single XML seam
(`SaxyTree.parse/1`) crashed instead of returning a typed rejection — violating
the "never crash, always a typed rejection" invariant on every entry point.
**Fixed** by making `SaxyTree.parse/1` convert any Saxy raise/exit into the same
`{:error, %Saxy.ParseError{}}` every caller maps to `:malformed_xml` (commit
`31fe63f`). Promoted to a permanent regression row in
`test/relyra/security/xml/saxy_tree_test.exs` (truncated/malformed prolog inputs
never raise; `Saxy.ParseError.message/1` also renders without raising). This is
the twin's headline result — a latent crash across all trust paths that manual
audit and local runs missed. **Stopping rule:** this defect resets the counter;
the next clean deep round (outside `ci-gate`, random seed) resumes it. The
bounded seeded lane gates every build.

## Phase 83 — mutation testing of the security core (commit `f3866f0`)

Mutare (compile-once) mutates the pure trust core and runs the covering tests per
mutant in a fresh `mix test` process. Scheduled lane
(`.github/workflows/mutation.yml`), JSON score artifact, outside `ci-gate`.

**Score trend — `algorithm_policy.ex`:**

| Round | Score | Killed | Survived | Ignored | Action |
|-------|-------|--------|----------|---------|--------|
| 1 | 79.4% | 201 | 52 | 0 | baseline; surfaced the allowlist-acceptance gap |
| 2 | 81.1% | 198 | 46 | 9 | killed the signature-allowlist gap; ignored the ecdsa fast-path equivalents |
| 3 | 82.8% | 202 | 42 | 9 | killed the digest-allowlist gap |

**Real gap closed:** `enforce_signature_method`/`enforce_digest_method` were only
ever tested with SHA-1 (rejection) — nothing asserted that the strong hashes the
default policy lists as allowed (rsa-sha384/512, sha384/512 digests) are
accepted. Fixed with data-driven acceptance tests using literal URI assertions.
**Equivalent mutant:** the ecdsa fast-path in `digest_atom_for_signature_method/1`
(same fall-through error) carries a documented `mutare:ignore`.

**Plateau:** the trend flattened once both allowlist gaps closed; the remaining 42
survivors are the type-only error-message/detail equivalence class (29) and a
defensive-guard / deprecated-SHA-1-escape-hatch residual (13). Further test-writing
would suppress equivalents, not detect defects — diminishing returns reached.

## Residual risk (recorded, not chased)

1. **`auto_refresh.ex` `extract_candidate_signing_pems/1`** scans candidate
   signing PEMs by byte regex BEFORE signature verification, then gates them by
   operator fingerprint pinning (pre-verify, trust-gated — not a derivation).
   A later pass can route it through the bound tree.
2. **Mutation scope** currently covers the pure trust core. The Ecto-backed
   replay stores and metadata-apply path are deferred (need the `mutare_ecto`
   companion for schema macros; their trust-relevant checks already route through
   the scoped modules). The scheduled lane extends the full-core score over time.
3. **Error message/detail mutants** are equivalent under the type-only error
   contract and the defensive-guard / legacy-SHA-1 edge mutants are residual, as
   recorded in the Phase 83 round log.
