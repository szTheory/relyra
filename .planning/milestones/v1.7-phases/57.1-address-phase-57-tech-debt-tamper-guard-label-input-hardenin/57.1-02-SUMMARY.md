# Phase 57.1 Plan 02: FakeIdP Input Hardening (WR-04, IN-03/WR-01, WR-03, WR-02) Summary

**One-liner:** Bounded `:zlib.safeInflate/2` loop with 64 KiB output ceiling, NCName-tightened ID extractor, catch-all idp_action dispatch, and corrected login label matching the emitted SAML subject.

## What Was Built

Four input-hardening changes confined to `demo/ledger_loop` — the FakeIdP's unauthenticated GET/POST boundary. No Relyra core files touched.

### WR-04: Bounded inflate (decompression-bomb mitigation)

Replaced single-shot `:zlib.inflate/2` in `inflate/1` with a `:zlib.safeInflate/2` loop driving a recursive `inflate_loop/4`. The loop accumulates output bytes and aborts to `:error` when they exceed `@max_inflated_bytes` (64 KiB). On a malformed stream, `safeInflate` raises and is caught by `rescue _ -> :error`. The existing `{:ok, binary} | :error` contract and the `with`/`else -> nil` map in `extract_in_response_to/1` are preserved — overflow silently collapses to `in_response_to: nil` with HTTP 200, no crash.

### IN-03/WR-01: NCName-tightened extractor

Tightened the ID capture regex from `~r/\bID="([^"]+)"/` to `~r/\bID="([A-Za-z_][A-Za-z0-9._-]*)"/` (ASCII NCName grammar). Non-name characters (`<`, `&`, space) are now rejected before the extracted ID can reach any downstream signer template. Added a comment documenting the first-match assumption (root `AuthnRequest/@ID` in a well-formed SP request). The real relyra-generated binding ID format (`_<hex>`, `id-<...>`) survives — confirmed by the SUCCESS round-trip in `fake_idp_flow_test.exs`.

### WR-03: Catch-all idp_action dispatch

Restructured the `case action do` in `sso/2` from `"success" -> ... ; "failure" -> ...` to `"failure" -> tamper ; _ -> success`. Any non-`"failure"` value — including crafted strings, arrays, or maps from multipart — resolves to the success path with HTTP 200. No `CaseClauseError`.

### WR-02: Corrected login label

Changed the valid-login radio label in `login.html.heex` from `Valid Login (evaluator@example.com)` to `Valid Login (sarah@northstar.example.com)`. `evaluator@example.com` is not a seeded `SAMLIdentity`; `sarah@northstar.example.com` is the actual subject emitted by `conn_fields/0`.
