<objective>
Harden the demo IdP signer's two emission-boundary responsibilities and the keypair loader's
diagnosability:

- WR-05: make `tamper/1` raise instead of silently no-op when it cannot locate `<NameID>`, so the
  demo's `:digest_mismatch` rejection proof can never become a false negative.
- WR-01: XML-escape every interpolated value inside `response_xml/3` so a metacharacter-bearing
  `in_response_to` (browser-supplied) cannot produce malformed emitted XML that crashes the signer's
  own re-parse.
- IN-02: replace the bare `[entry] = pem_decode(...)` MatchError with a typed match + descriptive raise.

Purpose: protect the integrity of the rejection proof (WR-05), close the XML-injection crash surface
on the FakeIdP emission path (WR-01), and improve key-load diagnosability (IN-02) — all confined to
`demo/ledger_loop`, with the Relyra verifier gate and the signer's anti-divergence guarantee untouched.

Output: hardened `signer.ex` + `keypair.ex` with new adversarial test rows; the existing success-path
verification stays green.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser → FakeIdP signer | `in_response_to` originates from the browser-supplied `SAMLRequest`, threads through the controller, and is interpolated into emitted XML in `response_xml/3` (untrusted input crosses into hand-built XML here) |
| demo test harness → Relyra verifier | The signed/tampered Response crosses into `do_verify/4`; the rejection proof's integrity depends on `tamper/1` actually tampering |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-57.1-01 | Tampering | signer.ex `response_xml/3` interpolation | mitigate | WR-01 — escape every interpolated value inside `response_xml/3` (attrs via `AttributeEscape.escape_attribute/1`, element text via `xml_text/1`); metacharacter `in_response_to` can no longer produce malformed XML that crashes the signer's own re-parse |
| T-57.1-02 | Repudiation / integrity-of-proof | signer.ex `tamper/1` | mitigate | WR-05 — broaden the match and raise on `tampered == xml`; the `:digest_mismatch` rejection proof can never silently become a false negative |
| T-57.1-03 | (Diagnosability) | keypair.ex `load_private_key/0` | mitigate | IN-02 — typed pattern-match + descriptive raise naming the key path and entry tags, replacing the opaque MatchError |

**Invariant check:** None of these touch the six CLAUDE.md non-negotiable invariants. The verifier
(`lib/relyra/**`) is untouched; the signer's anti-divergence guarantee (canonicalize via Relyra's own
`PureBeam.canonicalize` / `C14N.serialize`) survives because escaping is applied inside `response_xml/3`
*before* the signer re-parses its own output, and all three passes escape identically (digest stable).
No `Relyra.TestSupport.*` reference is introduced.
