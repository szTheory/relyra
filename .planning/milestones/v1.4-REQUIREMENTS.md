## v1.4 Requirements

Requirements for this milestone. Each maps to one roadmap phase.

### Single Logout (SLO)

- [x] **SLO-01**: Full SLO (Single Logout) round-trip (SP-initiated + IdP-initiated) with `SessionIndex` correlation. Extends the `Relyra.SessionAdapter` behaviour (`index_session/4` + `terminate_by_session_index/4` at canonical signature `(session_index, issuer, context, opts)`), enforces strict XMLDSig verification of `LogoutRequest`/`LogoutResponse` (POST: `Parse → Verify → Replay → Execute`; Redirect: `Verify → Inflate → Parse → Replay → Execute`), and provides replay protection across both bindings. Session-index registration is **host-owned**: `consume_response/3` returns the index on the `Principal` but does not auto-register it via `index_session/4`; hosts invoke the callback from their ACS controller. Documented as Section 3.1 of `guides/recipes/logout.md`.

## Out of Scope

Explicitly excluded. Documented to prevent scope creep.

| Feature | Reason |
|---------|--------|
| Auto-wired `index_session/4` from `consume_response/3` | Breaks Relyra's "host owns sessions" stance; host apps already control session creation timing and storage shape. Documented as host-owned linkage in `logout.md`. |
| Back-channel SOAP-binding SLO | Demand-gated; HTTP-Redirect and HTTP-POST cover the deployed enterprise IdP majority. |
| IdP-polling pattern (SP periodically pings IdP) | SAML has no standard `/userinfo` endpoint; explicitly discouraged in `guides/recipes/logout.md`. |
| Stateless cookie-based session stores for SLO | Cannot satisfy `terminate_by_session_index/4` semantics; explicitly disqualified in `guides/recipes/logout.md` (mandatory stateful session prerequisite). |
| HTTP-Artifact and ECP bindings | "Diminishing returns" boundary drawn at v1.0; demand-gated only. |
| Full standalone demo app | Library, not application; runs in adopters' Phoenix apps. |
