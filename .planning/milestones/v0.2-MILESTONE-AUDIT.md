### Notes

- **Integration WARNING (carried as tech debt, not blocking):** `MappingCommands.append_audit/8` does not explicitly call `repo.rollback/1` on `AuditWriter` failure inside its `with` chain — it returns `{:error, _}` and relies on Ecto's `transact/1` to auto-rollback. The other three co-commit sites (`Connections`, `MetadataApply`, `CertificateInventory`) all use the explicit-rollback pattern. On modern Ecto this is correct; on legacy Ecto where the helper falls back to `repo.transaction/1`, an audit failure could theoretically commit the mapping rows while reporting an error. Affects CFG-05 robustness on older adapters; not reproducible against the current dependency set (full suite 168/168 green).
- **Naming consistency:** `Relyra.Connection` (value struct) and `Relyra.Ecto.Connection` (schema) coexist correctly; the snapshot pattern-matches on the fully-qualified schema and produces the value struct.
- **Idp_certificates canonicalization:** `validation_pipeline.cert_chain/2` prefers `connection.idp_certificates`; snapshot fills both keys so legacy `:cert_chain` consumers remain served.
