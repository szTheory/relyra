# v1.0 Milestone Context

## Phase 25: Conformance and CVE Regression Fixtures

The following architectural decisions have been resolved for Phase 25 to ensure the security testing pipeline is robust, deterministic, and idiomatic for Elixir.

### 1. Test Execution Strategy
**Decision:** Native ExUnit with Fixtures (Data-Driven Testing).
**Rationale:** We will treat official Kantara XML test vectors and known CVE payloads as immutable data. An ExUnit parameterized test runner will feed these fixtures into our purely functional core. We will *not* require live external CI harnesses (like SAML2Int containers) for local `mix test` runs, preserving Elixir's fast, deterministic developer experience.

### 2. Fixture Sourcing Strategy
**Decision:** Hybrid "Port & Pin".
**Rationale:** To avoid "translation errors" and the high risk of crafting flawed XML Signature Wrapping (XSW) attacks from whitepapers, we will explicitly port the `test/fixtures/` corpora from mature, recently-audited libraries (like `ruby-saml` or `python3-saml`). This provides empirical proof against the exact payloads attackers have successfully used over the last 15 years.

### 3. Coverage Documentation
**Decision:** Auto-generated `CONFORMANCE.md`.
**Rationale:** The `CONFORMANCE.md` matrix will be auto-generated directly from the `priv/security_corpus.json` manifest via a Mix task or CI step. This guarantees that our security posture documentation is a "living document" perfectly in sync with the executed tests, preventing documentation drift.
