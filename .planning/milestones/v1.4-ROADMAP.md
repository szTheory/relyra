## Phase Details

### Phase 38: Single Logout (SLO) Core & Security

**Goal**: Users and Identity Providers can securely terminate sessions across the federation via verified SAML Single Logout flows.
**Depends on**: Phase 37
**Requirements**: SLO-01

**Success Criteria** (proven):

1. `Relyra.SessionAdapter` extended with `index_session/4` and `terminate_by_session_index/4` at canonical signature `(session_index, issuer, context, opts)`.
2. SP-initiated and IdP-initiated logout flows parse, generate, and process `LogoutRequest` and `LogoutResponse` for HTTP-Redirect and HTTP-POST bindings, built directly on the `SaxyTree` root node (single hardened parse path preserved).
3. All logout messages enforce strict XMLDSig signature verification before any session is terminated; HTTP-Redirect signatures verified against raw query octets via `Signature.verify_redirect_signature/4` (never re-serialized inside the function).
4. Strict replay protection rejects re-use of previously consumed logout messages as `:replayed_assertion`.

## Milestone Summary

**Decimal Phases:**

- Phase 40.1: v1.4 milestone-audit closure (inserted after Phase 40 on 2026-05-27 to close four audit findings before milestone archival)

**Key Decisions:**

- [Phase 38] SLO is built on top of the existing `SessionAdapter` behaviour rather than a new abstraction — `index_session/4` + `terminate_by_session_index/4` extend the contract additively; the four-arg canonical signature `(session_index, issuer, context, opts)` was chosen so the same callback works for both SP-initiated and IdP-initiated termination paths.
- [Phase 38] HTTP-Redirect logout signatures verify against the **raw query octets** — `Signature.verify_redirect_signature/4` receives a pre-assembled binary and never re-serializes inside the function. Same invariant as Phase 35's outbound `sign_redirect_query/3` (mirror of D-11 from v1.3).
- [Phase 38] `LogoutRequest` / `LogoutResponse` are built directly on the `SaxyTree` root node (`from_parsed_doc/1` routes through `parsed_doc.parse_tree`). No second parse path — CLAUDE.md non-negotiable #2 preserved.
- [Phase 38] The strict logout validation pipeline runs in fixed order: `Parse → Verify → Replay → Execute` for POST; `Verify → Inflate → Parse → Replay → Execute` for Redirect. Replay is gated **before** any adapter mutation; a tampered signature causes `refute_receive {:terminate_session, …}` to pass — order is **proven**, not assumed.
- [Phase 39] SLO is positioned as **structurally unreliable** due to modern browser privacy mechanisms (Safari ITP, Firefox ETP, Chrome Privacy Sandbox). Operators are explicitly told absolute timeouts on the SP side are the real security boundary; SLO is the optimization, not the guarantee.
- [Phase 39] **Stateful/durable server-side sessions are a strict prerequisite for SLO** — stateless Plug encrypted-cookie sessions are explicitly disqualified. `Relyra.SessionAdapter` must back onto PostgreSQL/Ecto/Redis or equivalent.
- [Phase 39] The "IdP polling" anti-pattern (SP periodically pinging the IdP for session state) is explicitly discouraged — SAML has no standard `/userinfo` endpoint.
- [Phase 40] Error taxonomy is bucketed into 7 trust-pipeline seams (Session & Logout merged into Binding & Protocol Shape per RESEARCH Step 2 to preserve drift parity). Each atom gets the four-field micro-block: Means / Likely root cause / Operator action / Source.
- [Phase 40] Drift test uses **three** code-atom regex patterns (single-line, multi-line, struct-literal) unioned against an H3 doc-atom regex — bidirectional `MapSet.difference` assertions catch both unsigned-doc atoms and stale doc entries.
- [Phase 40] Incident Playbook is a **narrative** stitched across five operator surfaces (telemetry, audit, LiveAdmin, Mix tasks, troubleshooting.md), not a reference. Six scenarios cover the high-frequency real-world failure shapes.
- [Phase 40] Replay storms get an explicit **no-audit-signal** callout — `ReplayStore` does **not** route through `AuditWriter` (load-bearing property cited verbatim from `lib/relyra/replay_store/{ecto,ets}.ex` frozen state).
- [Phase 40.1] `consume_response/3` does **not** auto-wire `SessionAdapter.index_session/4` — session-index registration is **host-owned**. Host apps invoke `MyAdapter.index_session/4` from their ACS controller after the principal is mapped to a local session. Documented as Section 3.1 "Session Index Mapping (host-owned)" in `guides/recipes/logout.md`. This keeps Relyra's "host owns sessions" stance internally consistent.
- [Phase 40.1] Drift prevention uses **AST-based arity** (`Code.string_to_quoted!/1` + arity counting) rather than naive `,`-splitting — protects against false positives on default args, capture syntax, or maps inside arg lists (WR-03 audit fix, commit e50e144).
- [Phase 40.1] Retroactive `38-VERIFICATION.md` and `39-VERIFICATION.md` follow the standard closure-phase pattern (analogous to v0.2's Phases 12/13/14, v0.5's Phases 21.1/21.2). Verification artifacts produced from existing evidence; no implementation re-opened.
