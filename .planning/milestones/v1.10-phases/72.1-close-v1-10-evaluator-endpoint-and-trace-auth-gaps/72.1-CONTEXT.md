# Phase 72.1: Close v1.10 evaluator endpoint and trace-auth gaps - Context

**Gathered:** 2026-08-27 (assumptions mode)
**Status:** Ready for planning

<domain>
## Phase Boundary

Close the two evaluator-path blockers identified by the v1.10 milestone audit: make the
SP settings shown by LedgerLoop correspond to the mounted, connection-scoped SAML routes,
and make the public launcher/documentation journey establish or explain the runtime
credentials required to inspect the authenticated operator trace. Both closures require
deterministic route/auth journey evidence.

This phase is limited to the demo host, Docker/launcher configuration, evaluator docs, and
their tests. It must not change `lib/`, Relyra's public API or behaviour callbacks, XML or
crypto seams, algorithm policy, replay protection, protocol behavior, the Hex package
whitelist, or any published package surface.
</domain>

<decisions>
## Implementation Decisions

### Connection-scoped SAML settings
- **D-01:** The setup journey must advertise metadata, ACS, and test-login URLs for the same
  enabled connection using the mounted `/saml/:connection_id/...` route family. The stale,
  unmounted `/auth/saml/metadata` and `/auth/saml/acs` values must not remain as operator
  configuration guidance.

### Evaluator route evidence
- **D-02:** Deterministic integration evidence must prove that the endpoint values rendered by
  Setup resolve to the actual metadata, login, and ACS route contract. A string/suffix assertion
  against rendered HTML alone is insufficient because it allowed the existing route drift.

### Admin authentication boundary
- **D-03:** Preserve fail-closed, runtime-supplied Basic Auth for `/login/admin` and the entire
  `/relyra/admin` mount, including validation traces. Do not introduce checked-in credentials,
  implicit usable defaults, a public trace bypass, or a route that establishes admin scope
  without authenticating through the existing host-owned boundary.

### Credential handoff journey
- **D-04:** Use an operator-chosen `DEMO_ADMIN_USERNAME` and `DEMO_ADMIN_PASSWORD` as an explicit,
  visible prerequisite before launching a journey that promises access to the operator trace.
  The Make-first launcher and evaluator documentation must explain the same credential handoff
  and the recovery path from a 401 challenge without printing or persisting secret values.
- **D-05:** Deterministic tests must cover both sides of the boundary: configured valid credentials
  reach the intended trace path, while missing, partial, and invalid credentials remain denied.
  The public Solo/FakeIdP and optional Fleet/Keycloak instructions must agree with the tested
  journey rather than relying on CI-only credential injection.

### the agent's Discretion
- Exact helper/module boundaries for deriving connection-scoped URLs, provided the displayed
  values and mounted routes share a drift-resistant contract.
- Exact placement and wording of credential setup instructions across `Makefile`, `.env.example`,
  and evaluator guides, provided credentials remain operator-chosen, runtime-only, and visible
  before the trace step.
- Exact split between LiveView, router/controller, and documentation drift tests, provided the
  evidence exercises routability and both authenticated and rejected admin paths.
</decisions>

<code_context>
## Existing Code Insights

### Reusable Assets
- The router already exposes the correct connection-scoped SAML route family through
  `saml_routes()` under `/saml`; no new protocol endpoint is needed.
- The FakeIdP and Keycloak tests already exercise successful scoped login/ACS flows and can anchor
  endpoint-routability evidence.
- `DemoAdminAuth` and the authenticated router scope already enforce the correct deny/allow
  boundary; the closure is a handoff and proof problem, not a request for a new auth system.
- Existing controller tests cover empty, partial, invalid, and valid credential cases, while the
  Keycloak harness already supplies owned per-run credentials without committing them.

### Established Patterns
- Browser-facing URLs use the runtime endpoint origin and a connection identifier; container-only
  service-DNS URLs never become operator-facing SAML settings.
- Demo admin credentials are runtime configuration with no usable source or Compose default.
- Evaluator proof distinguishes Relyra's validation trace from LedgerLoop's host-owned mapping and
  session-establishment receipt.
- New acceptance criteria require deterministic automated evidence in mandatory CI lanes; manual
  verification cannot be the completion gate.

### Integration Points
- SetupLive must obtain or select the connection identifier used to construct all three displayed
  SAML URLs.
- Rendered URL evidence must connect SetupLive to Phoenix's mounted metadata/login/ACS routes.
- The Make-first launch flow, Compose environment forwarding, `.env.example`, and both evaluator
  guides must present one coherent admin credential contract.
- Auth tests and the browser/harness proof must continue to demonstrate that denial remains the
  default and successful trace access requires the configured credentials.
</code_context>

<specifics>
## Specific Ideas

- Present the credential step before any launcher or guide instruction that says to inspect
  `/relyra/admin`; do not wait for the evaluator to discover the 401 challenge.
- Keep operator-selected secret values out of examples, generated output, logs, retained browser
  artifacts, and repository defaults. Placeholder variable names and shell invocation structure
  are acceptable; reusable passwords are not.
- Treat metadata, login, and ACS as one connection-scoped set so the UI cannot mix a real route for
  one operation with an unmounted or unscoped route for another.
</specifics>
