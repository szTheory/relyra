<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Docker daemon output → terminal | Container labels, names, status, and ports are untrusted display data from all local projects. |
| host process/network state → doctor | Tool output and configured network/port values cross into diagnostic messages and commands. |
| shell environment → Docker/network commands | `DEMO_PROXY_NETWORK`, `RELYRA_HOST`, and `PORT` influence quoted arguments or displayed values. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-71-05 | Tampering / Elevation | fleet and doctor shell recipes | high | mitigate | Quote every expansion, keep executable command tokens literal, never use `eval`, use no launcher temp files, and test hostile/missing display fields. |
| T-71-06 | Information disclosure | cross-project fleet output | medium | mitigate | Restrict output to project/name/status/ports fields, never print environment values, credentials, raw labels, mounts, or container inspection payloads. |
| T-71-07 | Denial of service | diagnostic failure handling | medium | mitigate | Preserve command status, distinguish query error from empty result, continue independent doctor checks, and never mutate containers from fleet/doctor. |
| T-71-08 | Spoofing / Repudiation | diagnostic states | medium | mitigate | Emit explicit OK/WARN/ERROR/OPTIONAL text, exact reasons and recovery commands, and never infer a free port when no probe ran. |

No npm, pip, or cargo package install occurs in this plan; the package-legitimacy supply-chain gate is not applicable. Generic command injection and Docker daemon authorization are canon and remain covered by T-71-05 and later `$gsd-secure-phase`; they are not minted as bespoke prohibitions.
</threat_model>
