# Phase 71 — UI Design Contract

> Visual and interaction contract for the Make/terminal launcher. The primary surface in this phase is command output, not a browser UI. Generated by gsd-ui-researcher and approved by gsd-ui-checker.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none — no React/Next.js/Vite surface or shadcn initialization applies |
| Preset | not applicable |
| Component library | none; GNU Make recipes and Bash compatibility adapter |
| Icon library | none; terminal output uses explicit text labels, never symbols alone |
| Font | terminal's monospace font; semantic source remains `JetBrains Mono, ui-monospace, SFMono-Regular, Menlo, Consolas, monospace` from `brandbook/tokens/tokens.css` |

**Rendering rule:** Output must remain fully understandable with ANSI disabled, in a non-TTY, and when pasted into an issue. ANSI decoration is optional and may only supplement the text hierarchy below; it must never convey status, scope, or required recovery action by colour alone.

---

## Spacing Scale

The terminal surface uses blank lines and indentation as its spatial system. Preserve this scale when a rendered format has pixel layout; use its proportional terminal equivalent in Make output.

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Equivalent of one space between a status label and its detail |
| sm | 8px | Equivalent of two-space indentation for a route or diagnostic detail |
| md | 16px | One blank-line-equivalent between a heading and its related rows |
| lg | 24px | One blank-line-equivalent between banner sections |
| xl | 32px | Major group separation: origins, routes, walkthrough, and operational notes |
| 2xl | 48px | Reserved for rendered documentation; not emitted as terminal padding |
| 3xl | 64px | Reserved for rendered documentation; not emitted as terminal padding |

Exceptions: terminal output must not use blank-line padding to simulate pixel spacing; each URL, status, and corrective command remains a separate short line so it survives narrow terminals and copy/paste.

## Typography

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body / diagnostic detail | 16px equivalent | 400 | 1.5 |
| Label / target name | 14px equivalent | 600 | 1.5 |
| Heading / section lead | 20px equivalent | 600 | 1.2 |
| Code / URL / command | 14px equivalent | 400 | 1.5 |

Terminal hierarchy is expressed in the literal text: `==> Section` for headings, fixed labels (`App:`, `Operator:`, `Next:`) for rows, and unmodified copy-pasteable URLs/commands. Do not rely on alignment padding for correctness: labels may align for legibility, but values must remain readable when wrapping.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `--rl-bg` / Paper `#FCFBF7` | Rendered-doc or terminal-background reference; terminal output remains neutral by default |
| Secondary (30%) | `--rl-surface-subtle` / Mist `#EEF2F6` | Rendered code/output panels and grouped diagnostic sections |
| Accent (10%) | `--rl-action` / Relay Blue `#3454D1` | Optional ANSI emphasis for the primary launch command, copyable URLs, and explicit `Next:` recovery commands |
| Destructive | `--rl-error` / Error `#B42318` | Optional ANSI emphasis for the `NUKE` warning only; literal warning text remains mandatory |

Accent reserved for: the `make up-d` primary launch command, displayed browser URLs, and each exact corrective command after `Next:`. It is not used for ordinary labels, optional Keycloak/Traefik links, or all interactive text. If optional ANSI color is added, status uses an explicit prefix (`OK`, `WARN`, `ERROR`, `OPTIONAL`) and never colour alone. Interactive boundaries in any rendered companion output use `--rl-border` / Accessible Border `#7E8A9A`, never decorative `--rl-divider`.

## Interaction Contract

### Command hierarchy and banner

- `make help` is the discovery surface. It opens with `Relyra demo launcher` and lists only the canonical target, one imperative description, and its topology where relevant. `scripts/demo` is not presented as a peer primary interface.
- `make up-d` is the primary CTA. After detached solo start succeeds, it invokes `make url` and emits the banner once. `scripts/demo urls` delegates to the same `make url` renderer; no second echo block is permitted.
- The `url` banner has this fixed reading order: **Browser origins**, **Route map**, **Walkthrough**, **Topology notes**. It always shows both `http://${RELYRA_HOST:-relyra.localhost}` and `http://localhost:${PORT:-4000}`; it must not hide either based on detected state.
- Every route is one complete, copy-pasteable line. Routes are `/`, `/relyra/admin`, `/login/test`, `/support/scenario`, and `/healthz`. The Keycloak route is `http://keycloak.${RELYRA_HOST:-relyra.localhost}/admin` and is labelled `OPTIONAL — fleet + keycloak profile`; Traefik is `http://localhost:8080/dashboard/` and is labelled `OPTIONAL — shared fleet proxy`.
- The walkthrough is numbered and FakeIdP-first: `1. Open Login test`, `2. Choose FakeIdP`, `3. Complete the sign-in`, `4. Inspect the operator trace`. It names the full route in the preceding map rather than embedding unstable IDs. Keycloak is a separate optional follow-up, never a prerequisite step.
- The topology note states exactly: `*.localhost is browser-facing; Docker health checks and internal probes use service DNS.` It does not imply that curl or container DNS can resolve `*.localhost`.

### Diagnostic and destructive feedback

- `make fleet` prints either `No Traefik-routed demo containers running.` followed by `Next: make proxy` (empty state), or the labelled Docker table for all `traefik.enable=true` containers. It does not filter to the Relyra Compose project.
- `make doctor` groups output as **Dependencies**, **Host ports**, **Shared proxy network**, and **Next steps**. It reports 4000, 5432, and 8080 independently. A 5432 listener is diagnostic only: its copy must say Relyra does not publish Postgres and must not present it as a launch blocker.
- A failing diagnostic line has three parts in order: explicit state, plain-language reason, exact recovery command. Example: `WARN proxy network missing. Next: make proxy`.
- When neither `lsof` nor `nc` is available, doctor says the probe is unavailable and gives the install/inspection next step; it must not report the port free.
- `reset` and `reseed` describe the same demo-data refresh. `nuke` is visually and verbally distinct: it names Relyra's Compose volumes/caches, warns that the next boot is a cold rebuild, and requires an affirmative confirmation. Default confirmation copy: `NUKE will permanently delete this Relyra demo's database, build, dependency, Hex, and Mix volumes. Continue? [y/N]`. A non-interactive invocation must require an equally explicit opt-in rather than silently proceeding.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA | `make up-d` — `Start the Relyra demo in the background, then print its routes.` |
| Empty state heading | `No Traefik-routed demo containers running.` |
| Empty state body | `Start the shared proxy with: make proxy; then start this demo with the fleet Compose command.` |
| Error state | `WARN {check} — {plain-language reason}. Next: {one exact corrective command}` |
| Destructive confirmation | `nuke`: `NUKE will permanently delete this Relyra demo's database, build, dependency, Hex, and Mix volumes. Continue? [y/N]` |

Voice is calm, exact, transparent, and operator-friendly. Use title-case product name `Relyra`; avoid cheerleading, vague success claims, or presenting optional demo credentials as production-safe secrets.

## UI Considerations

The post-verification probe classifies four terminal surfaces: launcher help/banner (`list-collection`, `static-content`), fleet output (`list-collection`), doctor report (`list-collection`, `static-content`), and nuke confirmation (`interactive-control`). All 24 applicable considerations are resolved: 16 covered explicitly, 8 dismissed with reasons, 0 backstop, and 0 unresolved.

| Surface | Category | Status | Resolution / Reason |
|---------|----------|--------|---------------------|
| Launcher help/banner | empty | dismissed | The canonical target list and route map are fixed contract content, not data-dependent collections; they are never rendered as an empty collection. |
| Launcher help/banner | loading | dismissed | Make execution is synchronous and streams native subprocess progress; the completed banner renders only after startup succeeds. |
| Launcher help/banner | error | ✅ covered | A failed startup preserves the underlying Make/Docker error and does not print a stale success banner or route map. |
| Launcher help/banner | populated | ✅ covered | The normal banner always renders browser origins, the complete route map, the four-step walkthrough, and topology notes in the fixed reading order. |
| Launcher help/banner | partial | dismissed | The route inventory is fixed: both proxy and loopback origins are always printed, while optional services remain present and explicitly labelled `OPTIONAL` rather than disappearing. |
| Launcher help/banner | overflow | ✅ covered | Every route and diagnostic is a standalone line; narrow terminals wrap naturally without clipping or truncating URLs and commands. |
| Launcher help/banner | zero-one-many | dismissed | The canonical target and route sets have fixed cardinality; this is not a user-sized collection. |
| Launcher help/banner | long-text | ✅ covered | Labels may wrap, but complete URLs, commands, walkthrough text, and topology notes are never ellipsized or alignment-dependent. |
| Fleet output | empty | ✅ covered | Zero matching `traefik.enable=true` containers render `No Traefik-routed demo containers running.` and an exact `Next: make proxy` recovery step. |
| Fleet output | loading | dismissed | The Docker query is synchronous; native command progress/error output is preserved and the fleet result renders only when the query returns. |
| Fleet output | error | ✅ covered | A failed Docker query is reported as an error with its reason and recovery action, never collapsed into the zero-container empty state. |
| Fleet output | populated | ✅ covered | One or more matches render the labelled project/name/status/ports table across all Compose projects, with no Relyra-only filter. |
| Fleet output | partial | ✅ covered | A matching container remains in the table when an individual display field is absent; the missing value is shown explicitly rather than dropping the row. |
| Fleet output | overflow | ✅ covered | Native terminal horizontal overflow or wrapping is allowed; container names, URLs, status, ports, and commands are never truncated by the launcher. |
| Fleet output | zero-one-many | ✅ covered | Zero uses the explicit empty state; one and many use the same labelled table and row spacing with no singular-only layout. |
| Doctor report | empty | dismissed | Doctor has a fixed inventory of dependency, port, and proxy-network checks, so it always emits the group headings and a result for every check. |
| Doctor report | loading | dismissed | Checks run synchronously and emit a result after each probe; no spinner, skeleton, or client-side loading state exists. |
| Doctor report | error | ✅ covered | Each failure states the check, a plain-language reason, and one exact `Next:` recovery command; an unavailable probe is not reported as success. |
| Doctor report | populated | ✅ covered | The normal report includes Dependencies, Host ports, Shared proxy network, and Next steps, with ports 4000, 5432, and 8080 reported independently. |
| Doctor report | partial | ✅ covered | One unavailable or failed check does not suppress other results; every check retains its own explicit state, including the non-blocking 5432 diagnostic. |
| Doctor report | overflow | ✅ covered | Each check and corrective command occupies a short standalone line and wraps naturally without clipping the command or reason. |
| Doctor report | zero-one-many | dismissed | The check inventory is fixed by the launcher contract, not determined by a variable user collection. |
| Doctor report | long-text | ✅ covered | Long reasons and recovery commands wrap in full; no meaning depends on column alignment and no command is ellipsized. |
| Nuke confirmation | long-text | ✅ covered | The full Relyra-scoped deletion list and cold-rebuild warning appear before the affirmative prompt; wrapping preserves the complete warning and the default remains no action. |
