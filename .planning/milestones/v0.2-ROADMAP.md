## Overview

Relyra v0.2 added durable trust-data for tenant-scoped SAML connections without leaking config blobs into runtime code. The milestone delivered persisted connection records, a runtime snapshot resolver adapter, metadata import/export with controlled refresh and provenance, certificate inventory with staged rollover, and persisted attribute/group mappings backed by a durable cross-domain audit ledger. The trust boundary stays exactly where v0.1 put it: only the verified XML node is consumed, runtime trust shifts only on explicit operator action, and every mutation co-commits an audit row inside the same transaction as the data it describes.

**Closure-Phase Pattern:**
- Phase 12 → produced 09-VERIFICATION.md (and repaired the metadata refresh regression that blocked it)
- Phase 13 → produced 10-VERIFICATION.md (and synced 10-VALIDATION.md to wave_0_complete)
- Phase 14 → produced 11-VERIFICATION.md
- Each closure phase is verifiable by inspecting the produced upstream-phase artifact rather than carrying its own VERIFICATION.md.

**Key Decisions:**
- Connection aggregate persists as `Relyra.Ecto.Connection` with internal binary PK + public `connection_id`; runtime consumers see only `%Relyra.Connection{}` value structs (no Ecto rows above the resolver boundary).
- `idp_certificates` is the canonical certificate field on the runtime snapshot; legacy `cert_chain` is preserved as a compatibility mirror.
- Metadata refresh stays operator-triggered; runtime trust never shifts implicitly. Newly fetched signing certs stage as `:next`; promotion is explicit action.
- All mutation modules (Connections, MetadataApply, CertificateInventory, MappingCommands) co-commit audit rows via the single `Relyra.Ecto.AuditWriter.append_event` seam inside the same transaction as the change.
- `Relyra.Metadata.refresh/2` uses optional `Req`; the host app opts in to the HTTPS dep.
- Audit events carry actor / cause / before+after view / redacted payloads — no XML, PEM, or key material in audit rows.

**Issues Resolved:**
- Phase 09 metadata refresh `:invalid_certificate_pem` regression repaired via Phase 12.
- Phase 10 `wave_0_complete: false` validation gap closed via Phase 13.
- Phase 11 verification orphan closed via Phase 14.
- Cross-domain audit drift eliminated: same-transaction audit capture across all four mutation modules.
- Resolver boundary contract stabilized: one canonical hydrator, deterministic certificate precedence.

**Issues Deferred:**
- LiveView admin surface (CFG-06) deferred to v0.3 — config storage was the prerequisite and is now stable.
- Bulk operations across many connections (CFG-07) deferred — useful later, not needed to prove the trust-data model.
- Scheduled metadata refresh automation (CFG-08) deferred — v0.2 ships explicit, controlled refresh; automation can wait until provenance is proven in adopter use.

The other three co-commit sites (Connections, MetadataApply, CertificateInventory) all use the explicit-rollback pattern. Modern Ecto: correct. Legacy Ecto fallback: theoretically vulnerable. Tracking for v0.3 cleanup.
