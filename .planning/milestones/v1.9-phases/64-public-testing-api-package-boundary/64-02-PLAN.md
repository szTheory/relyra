## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| public negative fixture -> verifier | Public helper outputs intentionally malformed or mismatched SAML inputs into the real verifier. |
| fixture trust material -> verifier | Wrong-key and valid-key cases rely on explicit returned cert chains only. |
| security test suite -> CI alias | New security coverage must run as an actual process, not a hollow Mix alias no-op. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T64-01 | Spoofing/Tampering | `tampered_digest/1` | mitigate | Mutate signed assertion content after signing and assert exact `:digest_mismatch` through `Relyra.consume_response/3`. |
| T64-02 | Spoofing | `invalid_signature/1` | mitigate | Return a distinct wrong cert chain and assert exact `:invalid_signature`; never rely on document `KeyInfo`. |
| T64-03 | Tampering | `Relyra.Testing.Signer` | mitigate | Reuse verifier-aligned parse/C14N signing from Plan 01 for all negative fixtures. |
| T64-04 | Information Disclosure | `Relyra.Testing` public negative API | mitigate | Publish only wrong audience, digest tamper, and wrong-key fixtures; source checks forbid `Relyra.TestSupport.*` in public testing modules. |
| T64-05 | Elevation of Privilege | `Relyra.Testing.consume_opts/2` with negative fixtures | mitigate | No helper mutates global trust; tests pass fixture data explicitly to `consume_response/3`. |
