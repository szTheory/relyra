<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| HTTP/login request -> request store | Untrusted RelayState and request context cross into request intent persistence. |
| Assertion ID -> replay store | Signed response values cross into replay protection storage. |
| Application config -> Relyra runtime | Demo config selects resolver and store behaviour modules. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-52-01 | Tampering / Elevation of privilege | `LedgerLoop.Relyra.RequestStore` and `ReplayStore` | mitigate | Fixed table constants and tests where caller opts try to override `table`; fixed opts must win. |
| T-52-02 | Spoofing | replay acceptance | mitigate | Unique `replay_key` index plus `Relyra.ReplayStore.Ecto` duplicate handling tested through wrapper. |
| T-52-03 | Tampering | request intent reuse | mitigate | Request table has unique `relay_state` and `{relay_state, request_id}` indexes and uses Relyra consume semantics. |
| T-52-04 | Spoofing | trust-source confusion | mitigate | Config uses `Relyra.ConnectionResolver.Ecto` against seeded configured certificates; no `KeyInfo` trust path added. |
| T-52-05 | Tampering | parser bypass | mitigate | Store wrappers do not parse XML and only persist Relyra behaviour payloads. |
| T-52-06 | Information disclosure | audit/trace or deterministic seed leakage | transfer | Plans 52-03 and 52-05 own audit/receipt redaction checks. |
| T-52-SC | Tampering | package installs | accept | No package-manager installs are planned. |
</threat_model>
