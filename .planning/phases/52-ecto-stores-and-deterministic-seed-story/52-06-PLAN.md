<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Signed SAML response -> Relyra consume path | Test support generates signed XML consumed by Relyra's existing parser and crypto path. |
| Relyra runtime -> Ecto stores | Request and replay behavior crosses into fixed LedgerLoop database tables. |
| Verified principal -> LedgerLoop host modules | Relyra hands verified identity to host mapper and session adapter. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-52-01 | Spoofing | signed response verification | mitigate | Use real Relyra test signing and existing `Relyra.consume_response/3`; do not bypass configured certificate trust or trust document `KeyInfo`. |
| T-52-02 | Spoofing | replay acceptance | mitigate | Assert first consume inserts replay key and duplicate consume returns replay rejection through Ecto replay store. |
| T-52-03 | Tampering / Elevation of privilege | request-derived table selection | mitigate | Assert request and replay rows land only in fixed LedgerLoop tables from Plan 52-04. |
| T-52-04 | Tampering | parser bypass | mitigate | LedgerLoop test code may build signed responses through Relyra test support but must not add a second XML parser or inspect XML fields outside Relyra. |
| T-52-05 | Information disclosure | receipt and trace proof | mitigate | Assert receipt contains ownership summary and not raw XML, PEM, SAMLResponse, RelayState, FakeIdP, Keycloak, or private key text. |
| T-52-06 | Repudiation | session receipt | mitigate | Assert receipt row is persisted with connection/user/tenant linkage and ownership fields. |
| T-52-SC | Tampering | package installs | accept | No package-manager installs are planned. |
</threat_model>
