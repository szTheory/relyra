<objective>
Deliver the core Phase 08 runtime boundary: a built-in
`Relyra.ConnectionResolver.Ecto` adapter that stays thin, an internal
aggregate loader that owns Ecto access, and a single snapshot hydrator
that turns a runtime-ready aggregate into a normalized `%Relyra.Connection{}`.
</objective>

<threat_model>
  <threat id="TM-08-02-BOUNDARY-LEAK" severity="high">
    If the public adapter performs queries and normalization inline, Ecto
    structs and repo concerns can leak into login/metadata runtime code,
    breaking the pure-runtime boundary and making later phases harder to
    extend safely.
  </threat>
  <threat id="TM-08-02-NORMALIZATION-DRIFT" severity="high">
    If provider defaults, derived fields, and certificate naming are
    applied in more than one place, login and metadata flows can observe
    different effective config from the same persisted connection.
  </threat>
  <mitigations>
    - Implement `Relyra.ConnectionResolver.Ecto` as request-context
      orchestration plus typed error mapping only per D-01 and D-02.
    - Put preload/query rules in `Relyra.Ecto.ConnectionLoader` and keep
      Ecto structs below the public boundary per D-03 and D-04.
    - Put all runtime default expansion, derived field construction, and
      `idp_certificates` canonicalization in one snapshot hydrator per
      D-05 through D-12.
    - Map not-found, draft/disabled, missing runtime fields, missing
      certificates, repo misconfiguration, and hydration failures into
      the small public taxonomy with precise `details.reason` per D-13
      through D-16.
  </mitigations>
  <verification_commands>
    - `mix test test/relyra/ecto/ecto_connection_resolver_test.exs --warnings-as-errors`
    - `mix test test/relyra/connection_snapshot_test.exs --warnings-as-errors`
    - `rg -n "Relyra.ConnectionResolver.Ecto|ConnectionLoader|ConnectionSnapshot|idp_certificates|details.reason|runtime_ready" lib/relyra/connection_resolver/ecto.ex lib/relyra/ecto/connection_loader.ex lib/relyra/ecto/connection_snapshot.ex`
  </verification_commands>
</threat_model>
