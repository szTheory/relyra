<objective>
Close Phase 08 by proving the same normalized snapshot contract reaches
every request-time consumer: login, metadata, and protocol validation.
This slice hardens the compatibility edge so `idp_certificates` is the
real runtime contract and `cert_chain` stays explicitly transitional.
</objective>

<threat_model>
  <threat id="TM-08-03-FLOW-DIVERGENCE" severity="high">
    If login, metadata, and protocol validation read different snapshot
    shapes or certificate fields, the same persisted connection can
    behave differently across request paths and silently reintroduce
    runtime normalization drift.
  </threat>
  <mitigations>
    - Update runtime consumer precedence so canonical
      `idp_certificates` is preferred over `cert_chain`, with the old
      field left only as explicit compatibility glue.
    - Add login and metadata controller tests that both resolve through
      the shared resolver seam and assert typed failures still propagate.
    - Reuse one fake resolver fixture across request-time consumers so
      boundary purity is proven consistently rather than by parallel,
      diverging fixtures.
  </mitigations>
  <verification_commands>
    - `mix test test/phoenix/login_controller_test.exs --warnings-as-errors`
    - `mix test test/phoenix/metadata_controller_test.exs --warnings-as-errors`
    - `mix test test/relyra/ecto/ecto_connection_resolver_test.exs test/phoenix/login_controller_test.exs test/phoenix/metadata_controller_test.exs --warnings-as-errors`

  </verification_commands>
</threat_model>
