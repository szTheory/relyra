<objective>
Add `saxy` as a non-optional runtime dependency (gated behind a package-legitimacy checkpoint),
then build the `Saxy.Handler`-based parse-tree builder that produces a structured tree carrying,
per element node: the verbatim qualified name, raw attributes in document order, and a computed
in-scope namespace stack inherited from ancestors — applying the three Relyra-owned infoset
normalization layers (in-scope ns stack, attribute-value whitespace normalization, line-ending
normalization) at build time.

This is the parse-substrate foundation for the whole phase. The exclusive-C14N engine (Plan 02)
and the seam re-wiring (Plan 03) both consume the tree-node shape defined here, so this plan also
fixes that shape as the contract those plans build against (interface-first ordering).

Purpose: Replace regex string-scanning with a real parse tree (SIGV-03, ROADMAP success #1) so a
single hardened parser trust path produces canonical-ready nodes. Saxy performs zero namespace
resolution, zero attribute-value normalization, and zero line-ending normalization — those three
layers are Relyra's responsibility (D-01, D-03) and the single biggest byte-divergence hazard.
Output: `{:saxy, "~> 1.6"}` in mix.exs + mix.lock; `lib/relyra/security/xml/saxy_tree.ex`.
</objective>
