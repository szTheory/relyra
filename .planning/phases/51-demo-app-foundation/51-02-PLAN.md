<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Browser -> LedgerLoop workspace | Untrusted evaluator/browser receives operational status and route affordances. |
| Workspace -> route affordance pages | Users can navigate to setup/login/support route affordances before those flows are implemented. |
| Workspace -> LiveAdmin route | Users can navigate from LedgerLoop host UI into mounted Relyra operator UI. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-51-06 | Information Disclosure | `home.html.heex` | mitigate | Tests must refute `BEGIN CERTIFICATE`, `SAMLResponse`, `Assertion`, `RelayState=`, `FakeIdP`, and `Keycloak`; do not render raw XML, PEM, secrets, assertions, or request params. |
| T-51-07 | Spoofing | `/login/test` route affordance | mitigate | Login route copy must state browser login proof is owned by Phase 54; Phase 51 must not present FakeIdP or Keycloak as production behavior. |
| T-51-08 | Repudiation | Workspace boundary copy | mitigate | The first screen must include `host-owned` and `Relyra verifies SAML trust` so evaluator evidence preserves host/Relyra responsibility boundaries. |
| T-51-09 | Tampering | CSS/layout assets | mitigate | Use app-local `app.css` only; no third-party UI registry, Tailwind, shadcn, React, or external asset pipeline in Phase 51. |
| T-51-10 | Denial of Service | First-screen navigation | accept | Static workspace and route affordance links are low-cost Phoenix responses; deeper flow load belongs to Phases 52-55. |
| T-51-SC | Tampering | UI dependencies | mitigate | Do not install npm/pip/cargo packages; no shadcn registry blocks; Hex dependencies already approved in `51-RESEARCH.md`. |
</threat_model>
