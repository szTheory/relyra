<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Docker/CI -> /healthz and /readyz | Automation consumes probe text and status codes to decide whether the app is booted or ready. |
| Browser/API caller -> LedgerLoopWeb.Router | Untrusted HTTP requests reach health routes without browser session state. |
| HealthController -> LedgerLoop.Repo | Readiness may cross from app code into database availability checks. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-51-07 | Information Disclosure | `HealthController.ready/2` | mitigate | Return only `ready` or `unavailable`; do not include database errors, credentials, request params, XML, PEM, assertions, or stack traces. |
| T-51-08 | Denial of Service | `LedgerLoop.Health.ready?/0` | mitigate | Use `LedgerLoop.Repo.query("SELECT 1", [], timeout: 1000)` for database readiness and no seed-data dependency. |
| T-51-09 | Tampering | `LedgerLoopWeb.Router` health routes | mitigate | Register `/healthz` and `/readyz` under `pipeline :health` with only `plug(:accepts, ["json"])`; route tests must fail if probes move under the browser pipeline. |
| T-51-10 | Repudiation | route/readiness tests | mitigate | Automated tests assert route mounts and deterministic readiness override states, creating executable proof for DEMO-04 and DEMO-05. |
| T-51-SC | Tampering | probe implementation | accept | No new packages are added; implementation uses generated Phoenix controller/router and Ecto repo primitives. |
</threat_model>
