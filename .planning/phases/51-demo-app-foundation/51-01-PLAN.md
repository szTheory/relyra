<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Browser -> LedgerLoopWeb.Router | Untrusted HTTP requests enter the demo host app. |
| LedgerLoopWeb.Router -> Relyra.Phoenix.Router | SAML metadata/login/ACS routing crosses from host route ownership into Relyra's maintained controller seam. |
| LedgerLoopWeb.Router -> Relyra.LiveAdmin.Router | Operator UI routing crosses into mounted LiveAdmin with host repo and host scope provider. |
| Docker/CI -> /healthz and /readyz | Automation consumes probe text and status codes to decide whether the app is booted or ready. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-51-01 | Spoofing | `demo/ledger_loop/mix.exs` | mitigate | Use `{:relyra, path: "../.."}` only; do not vendor Relyra, publish a demo package, or import `Relyra.TestSupport` for app boot. |
| T-51-02 | Tampering | `demo/ledger_loop/lib/ledger_loop_web/router.ex` | mitigate | Mount SAML with `Relyra.Phoenix.Router.saml_routes/1`; do not create custom metadata/login/ACS controller routes that could bypass CSRF skip or the single Relyra parse path. |
| T-51-03 | Elevation of Privilege | `LedgerLoop.Relyra.AdminScope` | mitigate | Implement `Relyra.LiveAdmin.ScopeProvider`; return `{:error, :unauthenticated}` when `session["admin_actor"]` is missing or blank. |
| T-51-04 | Information Disclosure | `HealthController.ready/2` | mitigate | Return only `ready` or `unavailable`; do not include database errors, credentials, request params, XML, PEM, assertions, or stack traces. |
| T-51-05 | Denial of Service | `LedgerLoop.Health.ready?/0` | mitigate | Use `LedgerLoop.Repo.query("SELECT 1", [], timeout: 1000)` for database readiness and no seed-data dependency. |
| T-51-SC | Tampering | Hex dependency scaffold | mitigate | Use packages approved in `51-RESEARCH.md` Package Legitimacy Audit; no npm/pip/cargo installs, no Tailwind/daisyUI/esbuild/shadcn/React packages. |
</threat_model>
