# Phase 51 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none |
| Preset | not applicable |
| Component library | Phoenix LiveView function components; no shadcn/radix/base-ui |
| Icon library | none for Phase 51; use text links/buttons until the demo app owns an asset pipeline |
| Font | Helvetica, Arial, sans-serif |

Source: `.planning/REQUIREMENTS.md` DEMO-03, UX-01; `.planning/research/STACK.md`; existing `Relyra.LiveAdmin` inline style precedent.

Contract:
- Build the first screen as the actual LedgerLoop workspace, not a marketing landing page.
- Use plain Phoenix templates/LiveView components and inline or app-local CSS. Do not introduce Tailwind, shadcn, React, or a third-party component registry in Phase 51.
- Keep LedgerLoop host-owned pages visually adjacent to mounted Relyra LiveAdmin: calm, operational, clear, and low-decoration.
- Every primary navigation target must be reachable from the first screen: setup, login, Relyra admin, and support.
- Relyra SAML routes must be visible as host-owned integration routes, with `/saml` shown as the mounted SAML scope and `/relyra/admin` shown as the operator admin scope.

## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Inline metadata gaps, badge inner offsets |
| sm | 8px | Compact label/value spacing, table cell padding |
| md | 16px | Default element spacing, card padding, form row spacing |
| lg | 24px | Page padding, section gaps, workspace header margin |
| xl | 32px | Empty state padding, major panel spacing |
| 2xl | 48px | First-screen vertical rhythm on desktop |
| 3xl | 64px | Reserved for later full-page flows; avoid on Phase 51 dashboard shell |

Exceptions:
- Interactive controls must have a minimum target size of 44px by 44px when rendered as standalone buttons or nav items.
- Compact table rows may use 8px vertical padding only when the linked row text remains at least 14px and the row has a larger click target.
- Existing mounted `Relyra.LiveAdmin` views may retain their established 12px internal gaps and 20px margins; LedgerLoop should not restyle those internals in Phase 51.

## Typography

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 16px | 400 | 1.5 |
| Label | 14px | 400 | 1.4 |
| Heading | 20px | 600 | 1.2 |
| Display | 28px | 600 | 1.2 |

Contract:
- Use exactly these four text sizes in Phase 51 UI.
- Use only 400 and 600 weights.
- Page display text names the workspace, e.g. `LedgerLoop Workspace`; supporting copy explains status and next actions.
- Use tabular numerals for health/readiness counters only if counters appear.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | #ffffff | Page background, primary workspace content, form fields |
| Secondary (30%) | #f0f4f8 | Header band, navigation strip, status panels, readiness panels |
| Accent (10%) | #0066cc | Primary CTA, active text links, focused route links, selected workspace nav item |
| Destructive | #c62828 | Unavailable readiness, typed rejection/error state, destructive actions only |

Accent reserved for: primary CTA, active/focused text links, selected workspace nav item, and route links that move the evaluator into setup/login/admin/support flows.

Semantic support colors:
- Success: #2e7d32 for booted/ready/enabled state labels.
- Warning: #b87600 on #fff7e6 for draft or setup-incomplete state labels.
- Neutral text: #555555 for supporting copy and metadata; #333333 for primary text.
- Borders: #d1d9e1 for panels and controls; #dddddd for low-emphasis dividers.

Contract:
- Status indicators must include explicit text such as `Ready`, `Needs setup`, `Unavailable`, or `Mounted`; color alone is never sufficient.
- Light/dark/system support is a v1.7 requirement, but Phase 51 may implement only light mode foundations if dark/system token hooks are named and do not block boot. Do not hard-code colors in a way that prevents later theme variables.
- Do not use gradients, decorative blobs, or illustration-heavy hero treatment.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA | Open SSO Setup |
| Empty state heading | No tenant data loaded |
| Empty state body | Run the demo reset command, then refresh this workspace to load Northstar Health and its SSO status. |
| Error state | LedgerLoop is running, but demo data is unavailable. Check the database connection and run the demo reset command before continuing. |
| Destructive confirmation | Demo reset: This will replace seeded LedgerLoop demo data. Continue? |

Additional Phase 51 labels:
- Workspace title: `LedgerLoop Workspace`
- Tenant status section: `Northstar Health SSO status`
- Setup link: `Open SSO Setup`
- Login link: `Start Test Login`
- Admin link: `Open Relyra Admin`
- Support link: `Open Support Scenario`
- SAML route label: `Mounted SAML routes: /saml`
- Admin route label: `Mounted operator routes: /relyra/admin`
- Health label: `Demo health`
- Readiness label: `Demo readiness`

Copy rules:
- Say `host-owned` when explaining LedgerLoop setup/session boundaries.
- Say `Relyra verifies SAML trust` when summarizing the library boundary.
- Do not expose raw XML, PEM blocks, secrets, unredacted assertions, or request parameters in the first-screen UI.
- Do not describe FakeIdP or Keycloak on Phase 51 first screen except as disabled/future links if routes are not implemented yet.

## Interaction Contract

Workspace layout:
- Use a two-zone shell: top workspace header, then a responsive grid of operational panels.
- Desktop grid: left column for tenant/status, right column for route/action panels. Minimum content column width is 280px.
- Mobile layout: single column in this order: workspace header, tenant status, setup/login/admin/support links, route mounts, health/readiness.
- No nested cards. Panels are direct children of the main workspace grid.

Required first-screen affordances:
- `Open SSO Setup` links to the host-owned setup route, even if Phase 51 renders a placeholder destination.
- `Start Test Login` links to the host-owned login start route or a disabled placeholder with text explaining the login proof lands in a later phase.
- `Open Relyra Admin` links to `/relyra/admin`.
- `Open Support Scenario` links to the host-owned support scenario route or a disabled placeholder with text explaining seeded scenarios land in a later phase.
- Route mount panel shows `/saml` and `/relyra/admin` as readable route scopes.
- Health/readiness panel distinguishes `Booted`, `Ready`, and `Unavailable` with text and status color.

States:
- Loading: show `Loading LedgerLoop workspace...` in body text size with no spinner requirement.
- Empty: use the copywriting contract empty state and keep all route labels visible if routes are mounted.
- Error: use the copywriting contract error state and keep `/healthz` and `/readyz` route references visible for operator diagnosis.
- Ready: show tenant name, SSO status, and all four primary links.

Accessibility:
- Every panel must have a semantic heading.
- Links and buttons must be keyboard reachable in DOM order matching visual order.
- Focus outline must be visible and may use accent color.
- Status labels must include text and should be discoverable by screen readers without relying on surrounding color.
