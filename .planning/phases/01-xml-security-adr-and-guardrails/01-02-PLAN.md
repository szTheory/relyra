<objective>
Freeze and scaffold the `Relyra.Security.XML` seam so downstream protocol code can only consume hardened parse/signed-node/canonicalization outputs and receives deterministic typed `%Relyra.Error{}` failures.
</objective>

<threat_model>
  <threat id="TM-02-SEAM-BYPASS" severity="high">
    Trust decisions can be made from raw XML or multiple parser paths if seam boundaries are not explicit and enforceable.
  </threat>
  <threat id="TM-02-NONDETERMINISTIC-ERRORS" severity="medium">
    Inconsistent error atoms for the same malicious input make CI gates flaky and can hide parser regressions.
  </threat>
  <mitigations>
    - Define one behaviour module with exactly three callbacks: `parse_safely/2`, `select_signed_node/2`, `canonicalize/2`.
    - Define a stable union of XML security error atoms in the seam contract and use `%Relyra.Error{type, message, details}` everywhere.
    - Add focused tests tagged `:xml_seam` and `:xml_errors` that assert callback shape and deterministic rejection atom mapping.
  </mitigations>
  <verification_commands>
    - `test -f mix.exs && test -d lib && test -d test`
    - `rg -n "@callback parse_safely|@callback select_signed_node|@callback canonicalize" lib/relyra/security/xml.ex`
    - `rg -n "defstruct \\[:type, :message, details: %\\{\\}\\]" lib/relyra/error.ex`
    - `mix test --only xml_seam --warnings-as-errors`
    - `mix test --only xml_errors --warnings-as-errors`
  </verification_commands>
</threat_model>
