<objective>
Create a permanent adversarial XML fixture corpus and enforce a deterministic, binary security acceptance bar in local aliases and CI (including conditional checksum enforcement for non-pure-BEAM strategies and a single-parser-path enforcement gate).
</objective>

<threat_model>
  <threat id="TM-03-CORPUS-GAP" severity="high">
    Missing or weak malicious fixtures let parser/canonicalization regressions reach production undetected.
  </threat>
  <threat id="TM-03-CI-DRIFT" severity="high">
    Security lanes can be bypassed if CI does not require OTP 27/28 matrix execution and explicit security commands.
  </threat>
  <threat id="TM-03-NIF-SUPPLY-CHAIN" severity="high">
    Hybrid/NIF builds can publish unverified binaries if checksum verification is optional or undocumented.
  </threat>
  <mitigations>
    - Seed at least 36 fixtures across seven required attack classes with expected rejection atoms in a manifest.
    - Add a dedicated `security_corpus` test lane and wire aliases `qa`, `ci.fast`, `ci.security`, `ci.integration`.
    - Enforce one parser trust path with a compile-time parser-path guard plus CI execution so parser usage outside the seam fails the build.
    - Treat GATE-02 as binary: all `parser_differential_and_c14n` fixtures must pass on OTP 27 and OTP 28 with zero regressions.
    - Add CI workflow with OTP matrix `[27, 28]` and conditional checksum verification step for non-pure-BEAM strategy.
  </mitigations>
  <verification_commands>
    - `rg -n "\"class\": \"xxe_entity_abuse\"|\"class\": \"signature_wrapping\"" test/fixtures/security/xml/manifest.json`
    - `mix test --only security_corpus --warnings-as-errors`
    - `mix test --only gate02_c14n --warnings-as-errors`
    - `rg -n "otp: \\[27, 28\\]|mix qa|mix ci.fast|mix ci.security|mix ci.integration|gate02_c14n|zero regressions" .github/workflows/security-gates.yml`
    - `rg -n "defmodule Mix\\.Tasks\\.Compile\\.ParserPathGuard|Saxy|SweetXml|xmerl" lib/mix/tasks/compile/parser_path_guard.ex`
    - `rg -n "sha256sum -c \\.planning/security/nif-checksums\\.txt" .github/scripts/verify_nif_checksums.sh`
  </verification_commands>
</threat_model>
