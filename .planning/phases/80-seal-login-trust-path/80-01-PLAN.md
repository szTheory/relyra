# Plan 80-01: Seal the login trust path

## Objective

Close seams S1–S4, S6–S11 and S20 (see `.planning/research/SUMMARY.md`). Each one becomes a permanent `trust_binding` corpus row, red before the fix and green after it, driven through the public `Relyra.consume_response/3`.

## Decisions

- **D-80-01 Enveloped only.** SAML core §5.4.1 requires enveloped signatures. The test signers emit them. `XmldsigSigner.sign_response/1` moves a legacy sibling `<Signature>` template into the Assertion, after its `Issuer`, and adds the enveloped-signature and exc-c14n Transforms. Callers keep their fixture shapes.
- **D-80-02 Namespace policy.** A security element matches when its namespace URI is the SAML or XMLDSig URI, or when it has no namespace. A foreign namespace URI never matches. No-namespace input stays accepted: inside the signed Assertion that content is covered by the signature, and outside it nothing is consumed.
- **D-80-03 Assertion cardinality.** Every element whose local name is `Assertion`, at any depth and in any namespace, counts toward the cardinality rule. Exactly one is allowed, and it must be a direct child of the `Response` root. More than one gives `:ambiguous_signed_node`. An Assertion that is not a direct child, or has no ID, cannot verify.
- **D-80-04 Response fields.** `Issuer` and `Status/StatusCode` come from the Response's direct children only. The Assertion `Issuer` must equal the configured IdP entity ID.
- **D-80-05 Subject confirmation.** Recipient, NotOnOrAfter and InResponseTo come from the first bearer `SubjectConfirmation`. `SubjectConfirmationData@InResponseTo` must equal the request ID when a request intent exists, and must be absent for IdP-initiated logins. The test signer copies the Response `InResponseTo` onto `SubjectConfirmationData` when a template omits it.
- **D-80-06 Response-only signatures** stay fail-closed (S5, INTEROP-01 deferred).
- **New error atoms** (additive): `:reference_mismatch`, `:signature_placement_invalid`, `:unsupported_canonicalization_method`, `:unexpected_root_element`, `:signed_node_binding_mismatch`, `:assertion_issuer_mismatch`, `:subject_confirmation_invalid`.
