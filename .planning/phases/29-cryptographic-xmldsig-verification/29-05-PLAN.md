<objective>
Close the SIGV-04 plumbing gap (D-13): upgrade the metadata-root pre-parse
(`auto_refresh.ex:pre_parse_for_signature/1`, currently regex-derived) so it surfaces the SAME
tree-bound crypto inputs the assertion path has, then prove SIGV-04 — a genuinely-signed metadata
root verifies via the SAME `do_verify` signature-math primitive, while operator-pinned `TrustAnchor`
fingerprint pinning still rejects a signature-valid-but-wrong-fingerprint root (pinning as
defense-in-depth, not pinning alone).

Purpose: Wiring crypto into `do_verify` (Plan 03) already makes the metadata path fail CLOSED — but
its candidates carry only `:xml_id`/`:xpath`/`:signed_xml` (regex-derived, Pitfall 2), so SIGV-04's
positive control can never reach `{:ok}`. Per RESEARCH Open Q1 the metadata root must route through the
tree builder (`SaxyTree.parse` + a metadata-root candidate variant) — the "one trust path" / D-04
philosophy — rather than extending the regex extractor (which re-introduces a parser differential).
`verify_metadata_root/4` already delegates to `do_verify/4`, so the crypto math is shared; only the
plumbing changes.

Output: a metadata-root signed-candidates variant in `pure_beam.ex` producing the canonical candidate
shape, the rewired `pre_parse_for_signature/1`, and the SIGV-04 positive + wrong-fingerprint negative
controls. Depends on Plan 04 (the genuine signer is reused to mint a genuinely-signed metadata root).
</objective>
