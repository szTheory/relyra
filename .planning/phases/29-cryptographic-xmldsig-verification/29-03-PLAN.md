<objective>
Rewrite the `[candidate]` arm of `verified_signed_node/4` (signature.ex:167-175 — THE published-hex
auth-bypass site, D-01) to perform real cryptographic verification: `:public_key.verify` of the
canonicalized `SignedInfo` against the public key extracted from the configured `cert_chain` PEM
(D-03/D-04), plus a `DigestValue` recompute over the canonicalized referenced element with a
constant-time compare (D-05). Only build `%SignedNode{}` when BOTH checks pass; otherwise return a
typed `%Relyra.Error{}` naming the failed check (D-08).

Purpose: This is the core of the fix — it closes the SAML authentication bypass. Because both
`verify/4` and `verify_metadata_root/4` delegate to `do_verify/4`, wiring the crypto once covers
SIGV-01/02 here and primes SIGV-04 for Plan 05. All existing trust gates (cert_chain present,
KeyInfo-trust rejection, duplicate-ID, algorithm allowlist, single-candidate selection) stay and run
BEFORE the crypto — do not touch them.

Output: real crypto in the `[candidate]` arm, a fail-closed PEM→pubkey helper, the two new error atoms
added to the `xml_error_type` union, and a dedicated crypto test file covering the negative controls
that do NOT require a genuine signer (forged/garbage SignatureValue, truncated/malformed DigestValue,
ECDSA, malformed cert). The genuine positive control + wrong-key/tampered-NameID negatives that need a
real signature land in Plan 04 (which has the D-11 signer).

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| document SignatureValue/DigestValue → crypto | attacker-controlled; decoded then verified against the CONFIGURED key — never trusted as-is |
| configured cert_chain → public key | the ONLY trust source for the verify key (never document KeyInfo) |
| referenced element → canonical bytes → digest | the bytes hashed must be the EXACT bound `:node` (anti-XSW, Phase 28 D-10) |

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-29-07 | Spoofing | Forged SignatureValue (valid structure) | mitigate | `:public_key.verify` false → `:invalid_signature` (SIGV-01) |
| T-29-08 | Tampering | Content tampering w/ reused signature (altered NameID) | mitigate | DigestValue recompute over canonicalized referenced element + constant-time compare → `:digest_mismatch` (SIGV-02; full NameID-tamper proof in Plan 04) |
| T-29-09 | Spoofing/Elevation | Wrong-key / attacker KeyInfo | mitigate | Key extracted ONLY from configured cert_chain (D-04); `key_info_trust == true` rejected before crypto (signature.ex:113-119, unchanged) |
