<objective>
Rewrite the `[candidate]` arm of `verified_signed_node` (signature.ex:167-175 — THE published-hex
auth-bypass site, D-01) to perform real cryptographic verification: `:public_key.verify` of the
canonicalized `SignedInfo` against the public key extracted from the configured `cert_chain` PEM
(D-03/D-04), plus a `DigestValue` recompute over the canonicalized referenced element with a
constant-time compare (D-05). Only build `%SignedNode{}` when BOTH checks pass; otherwise return a
typed `%Relyra.Error{}` naming the failed check (D-08).

This requires threading `cert_chain` down the call chain. Verified against the LIVE source:
`do_verify/4` (signature.ex:104) has `cert_chain`; `verify_algorithms_and_candidates/3`
(signature.ex:137) DROPS it; `verified_signed_node/4` (signature.ex:159) has the signature
`(parsed_doc, signature_method, digest_method, details)` and does NOT receive `cert_chain`. The
`[candidate]` arm reads the RAW candidate map off `parsed_doc[:signed_candidates]` (signature.ex:160),
NOT a `select_candidate` handle — this is the map Plan 02 enriched with the D-02 keys. Both signature
changes below are MANDATORY (not conditional): carry `cert_chain` from `do_verify/4` down to the
rewrite site.

Purpose: This is the core of the fix — it closes the SAML authentication bypass. Because both
`verify/4` and `verify_metadata_root/4` delegate to `do_verify/4`, wiring the crypto once covers
SIGV-01/02 here and primes SIGV-04 for Plan 05. All existing trust gates (cert_chain present,
KeyInfo-trust rejection, duplicate-ID, algorithm allowlist, single-candidate selection) stay and run
BEFORE the crypto — do not touch them.

Output: real crypto in the `[candidate]` arm, `cert_chain` threaded through
`verify_algorithms_and_candidates` + `verified_signed_node`, a fail-closed PEM→pubkey helper, the two
new error atoms added to the `xml_error_type` union, and a dedicated crypto test file covering the
negative controls that do NOT require a genuine signer (forged/garbage SignatureValue,
truncated/malformed DigestValue, ECDSA, malformed cert) PLUS a minimal genuine positive smoke that
proves the wiring actually reaches the crypto. The fuller positive control + wrong-key/tampered-NameID
negatives (and the existing-test triage) land in Plan 04 (which owns the D-11 signer).
