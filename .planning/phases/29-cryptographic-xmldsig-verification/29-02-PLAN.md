<objective>
Close the two data-plumbing gaps the crypto needs (D-02 + D-06/D-07): surface the base64
`DigestValue`, the base64 `SignatureValue`, and the `SignedInfo` tree node per signed candidate in
`pure_beam.ex`, and add the URI→digest-atom mapping (with ECDSA fail-closed) to `AlgorithmPolicy`.

Purpose: Today candidates carry only `:node`/`:signature_node`/`:transforms_node` (Phase 28); neither
base64 value is extracted anywhere (grep-confirmed). The crypto in Plan 03 cannot run without these
inputs. The digest-atom mapping is the single source of truth for which hash the verifier recomputes
and is where ECDSA is rejected before any verify attempt (Pitfall 5 — ECDSA must fail CLOSED).

Output: extended candidate map + handle carry-through, plus
`AlgorithmPolicy.digest_atom_for_signature_method/1`. This plan has NO file overlap with Plan 01, so
it runs in parallel.

| signature-method URI → digest atom | algorithm selection is a trust decision; an unhandled/ECDSA URI must reject, not silently pick a default |
