<objective>
Land the D-09/D-10 mixed-content C14N "Option-a" fix: model document order in the parse tree
and make the exclusive-C14N engine walk text and child elements in that order, then prove the fix
with a new Docker-minted mixed-content golden — while keeping the existing 887-byte golden green.

Purpose: This is the HARD precondition for every realistic positive control (D-10). Today
`C14N.render_element/3` emits `escape_text(node.text)` BEFORE all children (`c14n.ex:263`), so any
pretty-printed / inter-element-whitespace signed XML mis-canonicalizes vs libxml2 → the recomputed
`DigestValue` differs → `:digest_mismatch` on every genuine real-IdP fixture. Crypto (Plan 03) and
the positive controls (Plans 04/05) depend on this byte-correctness.

Output: ordered `content` field on `SaxyTree.Node` (`:text`/`:children` kept as derived views so no
downstream helper changes), document-order C14N rendering, and a committed mixed-content golden +
PROVENANCE row proving byte-equality (SIGV-02 byte-exactness leg).
</objective>
