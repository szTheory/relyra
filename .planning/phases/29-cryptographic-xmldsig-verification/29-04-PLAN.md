<objective>
Build the Phase-29-local genuine XMLDSig signer (D-11) and use it to prove the POSITIVE control — a
genuinely-signed Assertion verifies as `{:ok, %SignedNode{}}` (ROADMAP success #3) — plus the two
negative controls that require a real signature: wrong-key (`:invalid_signature`) and tampered-NameID
(`:digest_mismatch`).

Purpose: Without a positive control, an "always-reject" verifier would pass every negative test in
Plan 03. The genuine signer is the ONLY input that should remain `{:ok}` after the crypto lands. Per
D-12 it MUST canonicalize with the SAME C14N engine the verifier uses and be written so Phase 30 can
PROMOTE it into `FakeIdP` (no divergent second signer that would canonicalize differently). It reuses
`FakeIdP`'s EXISTING RSA-2048 keypair (D-11 — do NOT generate a second), filling the `DigestValue` /
`SignatureValue` that `FakeIdP.response_xml` omits today (fake_idp.ex:126-131).

Output: `Relyra.TestSupport.XmldsigSigner` (prod-guarded, test-support home) + positive/negative crypto
assertions feeding `Signature.verify/4`. Depends on the C14N Option-a fix (Plan 01) and the crypto
wiring (Plan 03) both being in place.
</objective>
