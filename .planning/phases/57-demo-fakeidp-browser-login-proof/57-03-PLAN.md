Relyra route shape (lib/relyra/phoenix/router.ex:28-33):
```
get  "/:connection_id/login"  LoginController :new   (SP-initiated mint + intent + redirect)
post "/:connection_id/acs"    ACSController   :create (consume_response with relay_state)
```
Mounted under scope "/saml" in the demo router → /saml/<…J0>/login and /saml/<…J0>/acs.

SP-initiated correlation (the InResponseTo requirement — Pitfall 2):
- /saml/:id/login (start_login) mints an AuthnRequest, stores intent keyed by RelayState (RelayState embeds request_id), redirects external to idp_sso_url with `SAMLRequest=<deflated b64>&RelayState=<token>`
- ACS consume_response(relay_state: ...) → RequestStore.fetch_intent(relay_state) → requires parsed_doc.in_response_to == intent.request_id
- So /fake_idp/login MUST read the inbound deflated base64 `SAMLRequest`, inflate it, parse the `ID` attribute, and thread it (hidden field) into /fake_idp/sso → Signer `in_response_to`. Inflate via :zlib raw inflate (-15 window, mirrors Binding deflate at binding.ex:11). The AuthnRequest XML carries `ID="..."` on `<samlp:AuthnRequest ...>` (authn_request.ex:56).
