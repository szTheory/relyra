<objective>
Deliver the strict consume path for Phase 2 by implementing ordered response/assertion validation (`issuer -> signature trust bind -> status/destination/audience/recipient/time`), requiring request intent input, and returning only typed protocol outcomes through `Relyra.consume_response/3`.
</objective>

<threat_model>
  <threat id="TM-02-03-ORDER-BYPASS" severity="high">
    If validation stages run out of order, unsigned or mismatched assertions can pass protocol checks before trust is established.
  </threat>
  <threat id="TM-02-03-SILENT-SUCCESS" severity="high">
    Returning non-typed failures or implicit success values from consume flow hides security failures from callers.
  </threat>
  <threat id="TM-02-03-TIME-WINDOW-DRIFT" severity="medium">
    Incorrect NotBefore/NotOnOrAfter/SubjectConfirmation handling with unbounded skew causes acceptance of expired or not-yet-valid assertions.
  </threat>
  <mitigations>
    - Implement one canonical pipeline (`Relyra.Protocol.ValidationPipeline.run/4`) with fixed ordered stages and short-circuit error returns.
    - Require `request_intent` contract in `Relyra.consume_response/3` (`request_id`, `connection_id`, `relay_state`, `in_response_to`) before downstream validation.
    - Enforce status, destination, issuer, audience, recipient, and temporal checks in dedicated modules (`Relyra.Protocol.Response`, `Relyra.Protocol.Assertion`) with stable error atoms.
    - Wrap unexpected exceptions into `%Relyra.Error{type: :internal_protocol_error}` so callers always get typed outcomes.
    - High-severity threats in this plan are blocking; do not mark the plan complete until all verification commands pass.
  </mitigations>
  <verification_commands>
    - `rg -n "@ordered_stages|parse_safely|issuer_connection_match|signature_verify|signed_node_bind|status|destination|audience|recipient|time_conditions" lib/relyra/protocol/validation_pipeline.ex`

  </verification_commands>
</threat_model>
