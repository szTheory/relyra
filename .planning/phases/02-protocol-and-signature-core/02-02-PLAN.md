<objective>
Implement the strict signature trust core for Phase 2 by enforcing configured-certificate verification only, binding consumption to the exact verified signed node, rejecting duplicate/ambiguous ID conditions, and enforcing SHA-256+ algorithm policy with explicit time-boxed SHA-1 override semantics.
</objective>

<threat_model>
  <threat id="TM-02-02-KEYINFO-TRUST-BYPASS" severity="high">
    Treating document-provided `KeyInfo` as a trust source allows attacker-controlled certificates to bypass configured IdP trust anchors.
  </threat>
  <threat id="TM-02-02-SIGNATURE-WRAPPING" severity="high">
    Verifying one node but consuming a different node enables wrapping attacks and silent trust-path compromise.
  </threat>
  <threat id="TM-02-02-ALGO-POLICY-DRIFT" severity="medium">
    Weak algorithm fallback (SHA-1 by default or expired override) weakens baseline cryptographic guarantees and makes downgrade attacks practical.
  </threat>
  <mitigations>
    - Implement `Relyra.Security.Signature.verify/4` to require configured cert chain input and reject `KeyInfo` trust elevation with `:untrusted_certificate`.
    - Return `%Relyra.Security.SignedNode{}` from signature verification and reject `candidate_count != 1` with `:ambiguous_signed_node`.
    - Reject duplicate XML IDs during verification (`:duplicate_xml_id`) before any success path.
    - Centralize digest/signature enforcement in `Relyra.Security.AlgorithmPolicy` with explicit SHA-1 override map requiring `reason` and future `expires_at`.
    - High-severity threats in this plan are blocking; do not mark the plan complete until all verification commands pass.
  </mitigations>
  <verification_commands>
    - `rg -n "def verify\\(parsed_doc, connection, cert_chain, opts \\\\ \\[\\]\\)|:untrusted_certificate|:ambiguous_signed_node|:duplicate_xml_id" lib/relyra/security/signature.ex`
    - `rg -n "defmodule Relyra\\.Security\\.SignedNode|defstruct \\[:xml_id, :xpath, :signed_xml, :signature_method, :digest_method\\]" lib/relyra/security/signed_node.ex`
    - `rg -n "def default\\(\\)|sha1|legacy_sha1|:deprecated_algorithm|:legacy_algorithm_override_expired" lib/relyra/security/algorithm_policy.ex`
    - `mix test test/security/signature_policy_test.exs --warnings-as-errors`
    - `mix test test/security/signed_node_binding_test.exs --warnings-as-errors`
  </verification_commands>
</threat_model>

<must_haves>
  - Signature trust root is configured cert input only; document `KeyInfo` cannot promote trust.
  - Exactly one verified signed node is required for success; ambiguity or mismatch yields typed rejection.
  - Duplicate XML IDs are rejected before any signed-node success path.
  - Algorithm policy defaults to SHA-256+ and only allows SHA-1 under explicit non-expired override with reason and expiry.
  - All new trust failures are represented as `%Relyra.Error{}` atoms (`:untrusted_certificate`, `:ambiguous_signed_node`, `:duplicate_xml_id`, `:deprecated_algorithm`) to preserve deterministic protocol-core behavior.
</must_haves>
