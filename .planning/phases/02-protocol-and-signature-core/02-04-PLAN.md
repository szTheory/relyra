<objective>
Eliminate Phase 02's fail-open behavior by extracting protocol and signature fields from the actual XML payload, removing synthetic security defaults, adding strict request-correlation guardrails, and ensuring every consume path success is backed by verified signed-node evidence. This plan does not claim full `PROT-04` closure (store-backed request intent lifecycle remains in Phase 3).
</objective>

<threat_model>
  <threat id="TM-02-04-UNSIGNED-PAYLOAD-SUCCESS" severity="high">
    Unsigned or structurally incomplete XML can currently return `{:ok, ...}` when fallback payload defaults satisfy downstream checks.
  </threat>
  <threat id="TM-02-04-CORRELATION-BYPASS" severity="high">
    Missing `InResponseTo` and RelayState binding allows unsolicited or cross-request responses to be accepted.
  </threat>
  <threat id="TM-02-04-ALGORITHM-POLICY-MASKING" severity="medium">
    Signature/digest algorithm policy can be evaluated against defaults instead of values extracted from signed XML.
  </threat>
  <mitigations>
    - Extend parser output to extract response/assertion/signature fields required by protocol and trust checks; fail closed when required fields are absent.
    - Remove permissive fallback payload construction in validation pipeline and consume only extracted fields from `parse_safely/2`.
    - Enforce request correlation (`InResponseTo` and posted RelayState) before success result construction.
    - Require algorithm checks to run on extracted signature/digest methods from XML, not synthesized defaults.
    - High-severity threats in this plan are blocking; do not mark plan complete until all verification commands pass.
  </mitigations>
  <verification_commands>
    - `rg -n "extract_(response|assertion|signature)_fields|:missing_protocol_field|:missing_signature" lib/relyra/security/xml/pure_beam.ex`
    - `rg -n "def run\\(response_payload, request_intent, connection, opts \\\\ \\[\\]\\)|validate_request_correlation|:in_response_to_mismatch|:relay_state_mismatch|:relay_state_missing" lib/relyra/protocol/validation_pipeline.ex`
    - `rg -n "enforce_signature_method|enforce_digest_method|:deprecated_algorithm|:legacy_algorithm_override_expired" lib/relyra/security/signature.ex`
    - `mix test test/protocol/consume_response_pipeline_test.exs --warnings-as-errors`
    - `mix test test/security/signed_node_binding_test.exs --warnings-as-errors`
  </verification_commands>
</threat_model>

<must_haves>
  - `parse_safely/2` supplies required response/assertion/signature fields from actual XML payload and fails closed when mandatory values are absent.
  - `ValidationPipeline.run/4` no longer builds protocol/security defaults that can satisfy trust checks without signed payload evidence.
  - `consume_response/3` enforces `InResponseTo` and RelayState correlation with deterministic typed failures.
  - Signature and digest algorithm policy is evaluated against extracted XML methods only, preserving strict SHA-256+ default behavior.
  - Unsigned payloads cannot return `{:ok, ...}` through any consume path.
  - Correlation checks in this plan are Phase 2 guardrails; full `PROT-04` store-backed lifecycle semantics remain Phase 3 scope.
</must_haves>
