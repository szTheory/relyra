<spec>
**index.html sections (in order):**
1. Cover/hero — `logo-primary.svg`, tagline "Enterprise SAML, calmly verified.", one-line what-it-is, the theme toggle (Light / Dark / System).
2. Logo usage — embed `logo-primary`, `logo-stacked`, `logo-mark`, `logo-mark-mono`, `logo-typemark`, `favicon`, `logo-with-tagline`, `logo-primary-inverse` (the last on a dark panel). Clear-space + min-size notes. A do/don't grid (don't: cage it, stretch, add subtitle to primary, recolor off-brand, low-contrast bg). Marks shown cage-free.
3. Color — swatch cards for every semantic token (light + dark), each with hex + role + a WCAG contrast badge (ratio + PASS, lifted from accessibility-checks.md). Note Info==Relay Blue (icon+label affordance).
4. Typography — the scale (hero→caption + code) rendered in the real fonts (load IBM Plex Sans Condensed + Atkinson Hyperlegible + JetBrains Mono via Google Fonts CDN), with size/line-height/weight labels.
5. Space / radius / shadow — visual specimens of the space scale (2–128), radius (sm/md/lg/full), shadow (sm/md).
6. Components (light AND dark, every state) — buttons (default/hover/focus/active/disabled/loading), links, text inputs (default/focus/error/disabled), cards, callouts/alerts (info/success/warning/error — each with icon+label, never color alone), code block (protocol fields in JetBrains Mono), badges/tags, a table (tabular nums), empty state, loading skeleton, selected state.
7. Microcopy — do/don't pairs in the Relyra voice (calm/exact/transparent). Error pattern: what happened / why it matters / what to do. Forbidden claims callout (no unhackable/bulletproof/military-grade/zero-risk/"SAML is easy").
8. Developer notes — how to consume tokens.css (`--rl-*`), the theme hook (`[data-theme]` + prefers-color-scheme), focus-ring token, fonts, and a pointer to tailwind.example.js.

**Theme toggle:** a small JS that sets `data-theme` on `<html>` to light/dark or removes it for system; persists in localStorage; tokens.css already supplies the dark values.

**Scoping:** wrap the book's own layout CSS so it doesn't fight the tokens; rely on tokens.css for color/type/space. No CSS resets beyond a scoped `box-sizing`. Inline `<style>` for layout is fine; semantic colors must come from `var(--rl-*)`.

**examples/:**
- `components.html` — a minimal standalone page (links tokens.css) with the button/input/card/callout/badge/code-block markup copy-ready, commented.
- `landing-page-section.html` — a marketing hero + a 3-up feature section using the tokens + logo, copy in brand voice.
- `readme-header-example.md` — a Markdown README header (centered logo `<img>` referencing assets, tagline, badges placeholder, one-paragraph positioning) adopters can paste.
</spec>
