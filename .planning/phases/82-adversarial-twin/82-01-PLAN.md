# Phase 82 Plan: Property-based adversarial twin

Build a generative adversarial twin over the trust paths sealed in Phases 80/81
and prove the verified-node == consumed-node invariant holds under mutation.

## Approach

- Add `{:stream_data, "~> 1.4", only: [:dev, :test], runtime: false}` +
  `import_deps: [:stream_data]`.
- Generalize the test signer: `XmldsigSigner.sign_enveloped/1` signs an arbitrary
  enveloped-signed ROOT (the signing counterpart to Phase 81's
  `PureBeam.bind_enveloped_signature/3`), so the twin can mint genuinely signed
  LogoutRequest and EntityDescriptor documents.
- `test/support/twin/`: `Mint` (signed base + signed-field truth), `Mutations`
  (total, shrinkable op catalog across every family), `Generators` (StreamData
  plans), `Runner` (sign-then-mutate / mutate-then-resign), `Oracle` (invariant
  + bounded-task isolation + typed-rejection allowlist).
- `adversarial_property_test.exs`: per-kind + all-kinds properties, generator
  coverage, oracle planted-bug meta-test, twin self-tests. Bounded+seeded via
  `TWIN_MAX_RUNS`.
- Wire the lane into `ci.security` + the three mirror lists; add the scheduled
  `adversarial-deep.yml` (outside `ci-gate`).

## Verification

`mix qa`, `mix ci.security`, `mix format --check-formatted` exit 0; the property
