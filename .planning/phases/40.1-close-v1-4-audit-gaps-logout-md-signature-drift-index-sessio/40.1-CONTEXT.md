<decisions>
## Implementation Decisions

### A. `index_session/4` policy (THE central decision)

- **D-01:** Adopt option **(a) host-owned linkage** — do NOT auto-wire `consume_response/3` to call `SessionAdapter.index_session/4`. Document host responsibility in `guides/recipes/logout.md`: hosts invoke `MyAdapter.index_session/4` from their ACS controller after `Relyra.consume_response/3` returns, using `login_result.principal.session_index`.
  - Rationale: `lib/relyra/session_adapter.ex:96-126` makes `index_session/4` a top-level dispatch helper with telemetry — designed for host invocation, identical to `establish_session/3` which is also explicitly host-invoked. CLAUDE.md "Key Architecture Seams" rule: behaviour seams are "never bypass." Auto-wiring would commit Relyra to a session-storage policy at index time, violating host-owned-sessions stance. The asymmetry with `consume_logout/3` auto-wiring `terminate_by_session_index/4` (`lib/relyra.ex:343-361`) is defensible — terminate operates entirely on inbound-message data, but index needs the host's local session ID Relyra does not have.
  - Anti-bypass: This decision is reversible. If a future audit demands auto-wiring, add it post-`normalize_consume_result/1` without breaking the current contract.

### B. `logout.md` rewrite scope

- **D-02:** Rewrite scope is the code block at `guides/recipes/logout.md:100-127` PLUS the immediately surrounding narrative at lines 91-99 (where the current text "Relyra extracts this and passes it to your adapter" is misleading post-D-01 — Relyra does NOT pass `session_index` to `index_session/4`; the host reads it from `login_result.principal.session_index`).
- **D-03:** Add a 2-3 sentence operator paragraph between sections 3 and 4 documenting the host-owned linkage pattern from D-01.
- **D-04:** Leave sections 1, 2, 4 byte-untouched. They were verified satisfied by the audit's DOCS-04 evidence; only the code-block area failed.
