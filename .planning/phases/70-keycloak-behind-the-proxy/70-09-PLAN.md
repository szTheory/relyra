<objective>
Close the Phase 70 audit blocker by making the durable Sarah identity mapping, its matching audit evidence, and final Keycloak connection enablement one fail-closed transaction.

Purpose: The current provisioner inserts `SAMLIdentity` directly before a separately committed enable operation. That permits unaudited authorization state and lets the mapping survive enablement failure, violating D-05 and the project's non-negotiable audit co-commit invariant.
Output: A production-quality atomic finalization path and adversarial ExUnit regressions proving success evidence, audit-failure rollback, enablement-failure rollback, and idempotent retry behavior.
</objective>

The word `optional` describes whether the Keycloak proof profile is selected; it does not make identity mapping optional, move its anchor, or generalize the Relyra connection/identity model. FakeIdP remains the default independent lane.
</assumption_delta_decision>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| provisioner descriptor/trust state -> host identity mapping | Configured Keycloak trust is converted into a durable issuer/subject authorization mapping owned by LedgerLoop. |
| host identity mapping -> audit ledger | Every durable mapping mutation must gain attributable, append-only evidence in the same database transaction. |
| draft trust -> enabled connection | The connection becomes login-capable only after the identity and audit writes can commit together. |

## STRIDE Threat Register — ASVS L1, block high

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-70-41 | Repudiation | `SAMLIdentity` creation | high | mitigate | Insert the identity and append its attributed `domain: :mapping` event inside one outer Repo transaction; audit failure explicitly rolls back both. |
| T-70-42 | Elevation of privilege | enablement failure after identity insert | high | mitigate | Include `Connections.enable/2` in the same outer finalization transaction and prove injected enable failure leaves no identity or mapping audit residue. |
| T-70-43 | Tampering | idempotent retry/concurrent duplicate | medium | mitigate | Use exact issuer/subject uniqueness, re-read within the transaction, emit an event only for a real insert, and assert exact cardinality after failure/retry and unchanged rerun. |
| T-70-44 | Information disclosure | mapping audit summary | medium | mitigate | Persist only bounded identity-map references and attribution; exclude assertions, descriptor XML, PEM, credentials, private keys, and other sensitive material through AuditWriter normalization. |
| T-70-45 | Denial of service | transaction or audit writer failure | low | accept | Fail closed with the existing typed layer result and post-error disable safeguard; the profile remains optional and retryable. |
</threat_model>
