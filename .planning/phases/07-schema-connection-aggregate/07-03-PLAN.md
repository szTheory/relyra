<objective>
Prove the Phase 07 record workflow end-to-end without crossing into
Phase 08: add the minimal host-Repo persistence API for create/update/
disable, split draft persistence from runtime readiness, and align the
runtime value object with the public `connection_id` contract.
</objective>

<threat_model>
  <threat id="TM-07-03-DRAFT-RESOLVES-SILENTLY" severity="high">
    If draft or disabled rows are treated as runnable, Phase 08 can
    accidentally resolve incomplete trust records into the login path.
  </threat>
  <threat id="TM-07-03-RUNTIME-ID-MISMATCH" severity="medium">
    If `%Relyra.Connection{}` omits `connection_id`, later hydration can
    collapse public identity into the internal PK or `id` fallback.
  </threat>
  <mitigations>
    - Add a minimal persistence API that accepts `opts[:repo]` and
      performs only Phase-07-scoped record operations.
    - Keep draft-save and runtime-ready validation paths explicit.
    - Add `connection_id` to `%Relyra.Connection{}` now, without pulling
      in resolver hydration or Ecto structs.
  </mitigations>
  <verification_commands>
    - `test -f lib/relyra/ecto/connections.ex`
    - `rg -n "create|update|disable|enable|opts\\[:repo\\]" lib/relyra/ecto/connections.ex`
    - `rg -n ":connection_id" lib/relyra/connection.ex`
    - `mix test test/relyra/ecto/connection_record_test.exs test/relyra/ecto/runtime_readiness_test.exs test/relyra/connection_test.exs --warnings-as-errors`
  </verification_commands>
</threat_model>
