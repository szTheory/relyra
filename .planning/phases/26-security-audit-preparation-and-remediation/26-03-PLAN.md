## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| External findings -> repo ledger | Audit findings must be recorded, dispositioned, and tied to release policy inside the repo rather than a spreadsheet-only side channel. |
| CI alias execution -> release readiness | Security review artifacts and proof lanes become merge and release gates. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-26-08 | Repudiation | `docs/security_findings.md` | mitigate | Require a checked-in ledger with severity, exploit path, owner, disposition, blocker state, and regression link for every finding. |
| T-26-09 | Denial of Service | `mix.exs` security aliases | mitigate | Serialize migration-backed proof commands so repo-backed verification does not collide or flake under parallel execution. |
| T-26-10 | Tampering | `mix.exs` + `SECURITY.md` | mitigate | Make packet drift and proof lanes part of `ci.security`, and point public policy at the canonical packet + findings ledger instead of ad hoc release judgment. |
</threat_model>
