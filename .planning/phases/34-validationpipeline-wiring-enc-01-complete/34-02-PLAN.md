<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| test fixture generator -> SP decrypt path | FakeIdP.encrypt produces ciphertext the SP pipeline decrypts. A divergent recipe could mask a real canonicalization or auth-tag bug. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-34-04 | Tampering | namespace-context corruption on splice (HIGH) | mitigate | The encrypted `<Assertion>` carries its OWN `xmlns="urn:oasis:names:tc:SAML:2.0:assertion"` (Pitfall 1); sign-then-encrypt so post-decrypt bytes are byte-identical to the signed bytes. Round-trip test proves identity. Without this the positive control would spuriously `:digest_mismatch` (or, worse, a compensated fixture could mask real tamper). |
| T-34-05 | Tampering | GCM auth-tag / CipherValue layout | mitigate | Use the exact IV(12)||CT||Tag(16), 16-byte tag layout XMLEnc.split_cipher_value/1 round-trips (Pitfall 4). Round-trip test fails closed (`:decryption_failed`) if the layout diverges. |
| T-34-06 | Information Disclosure | private key in test plumbing | mitigate | The SP private key lives only in `:sp_private_key_pem` test env (deleted on_exit); FakeIdP.encrypt uses only the PUBLIC key `{:RSAPublicKey, n, e}` derived from keypair(). No private key in the encrypt path. |
</threat_model>
