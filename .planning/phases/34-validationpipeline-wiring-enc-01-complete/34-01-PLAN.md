<objective>
Extend `Metadata.build_sp_metadata/2` to publish both `<md:KeyDescriptor use="signing">` and
`<md:KeyDescriptor use="encryption">` inside `<md:SPSSODescriptor>` (ENC-02). The encryption
descriptor lets an encryption-enabled IdP encrypt assertions to the SP. This is the metadata
half of Phase 34 and is independent of the decrypt pipeline.

Purpose: ENC-02 — an IdP must be able to discover the SP encryption cert from metadata to
encrypt assertions; the signing descriptor is created unconditionally here (D-05), and Phase 35
later layers toggle-gating on top of it.
Output: An extended `build_sp_metadata/2` emitting both descriptors in schema-valid order, plus
a metadata test asserting their presence, ordering, and certificate body.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| operator config -> metadata XML | SP cert PEMs read from app env and embedded into served metadata. PUBLIC certs only. |
| SP metadata -> IdP | Published metadata is read by IdPs to choose an encryption cert. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-34-01 | Information Disclosure | build_sp_metadata/2 cert source | mitigate | Read ONLY `:sp_signing_cert_pem` / `:sp_encryption_cert_pem` (PUBLIC certs); NEVER `:sp_private_key_pem`. Acceptance criteria assert the private-key key string is absent from the source. (CLAUDE.md key-material invariant; RESEARCH V9.) |
| T-34-02 | Tampering | KeyDescriptor schema ordering | mitigate | Emit KeyDescriptors BEFORE AssertionConsumerService and KeyInfo before EncryptionMethod (RESEARCH Pattern 2); a schema-invalid descriptor an IdP rejects silently degrades to unencrypted/failed login. Ordering asserted in the metadata test. |
| T-34-03 | Spoofing | advertised EncryptionMethod URIs | mitigate | Advertise EXACTLY the XMLEnc accept-list (`xmlenc#aes256-gcm`/`aes128-gcm`/`rsa-oaep-mgf1p`); advertising an algorithm the decryptor hard-rejects (PKCS1v1.5, CBC, xmlenc11#) would invite the IdP to encrypt with bytes the SP can never decrypt. (RESEARCH A2.) |
</threat_model>
