<objective>
Extend `Binding.encode_redirect/3` IN-PLACE to: (a) apply raw-DEFLATE (RFC 1951; `:zlib`
window bits `-15`) before base64-encoding the XML — UNCONDITIONALLY for both signed and
unsigned paths (D-04, fixes pre-existing bug at lines 9-19); (b) accept `:sign`,
`:signing_key_pem`, `:signature_method`, `:encoding` opts; (c) when `:sign: true`, assemble
the OASIS §3.4.4.1 signed octet template verbatim, call `Signature.sign_redirect_query/3`,
and return `{:ok, %{redirect_query: bytes}}`; (d) apply ADFS lowercase-hex post-process
when `:encoding: :adfs_lower`.

Purpose: Closes the latent v0.1 deflate bug AND adds the signed-redirect-encoding entry
point downstream plans need. Per RESEARCH.md §3.2, in-place extension is the right shape
(rejected: sibling `encode_signed_redirect/4`) because deflate is shared 100% between
signed/unsigned paths and a sibling would double the surface area for the fix.

Output: Modified `binding.ex` (one function extended in-place + two private helpers
`deflate_xml/1` and `lowercase_hex/1`); modified `binding_test.exs` (existing assertions
fixed + new describe block for raw-DEFLATE round-trip); modified `sp_conformance_test.exs`
(two assertions at lines 71, 133 updated to round-trip-inflate shape).
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| caller (Relyra core / Phoenix controller) → `Binding.encode_redirect/3` | XML binary + RelayState string cross from validated core into binding layer; `:sign` flag is operator-policy-driven |
