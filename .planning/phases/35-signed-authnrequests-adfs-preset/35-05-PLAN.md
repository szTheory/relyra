<objective>
Thread the signed redirect-binding bytes produced by `Binding.encode_redirect/3` (Plan 02)
through `Relyra.start_login/3` and the Phoenix `LoginController` so the controller appends
the pre-assembled OASIS §3.4.4.1 signed query-string VERBATIM to `idp_sso_url` — never
calling `URI.encode_query/1`, `URI.decode_query/1`, or `Map.merge/2` on the signed bytes.
This is the load-bearing wiring task: every prior plan exists to produce these bytes; this
plan is the one that lets a real `Plug.Conn` carry them to the IdP intact.

Purpose: Closes the T-35-01 re-serialization auth bypass at the controller layer — the
CVE-class footgun OASIS §3.4.4.1 lines 620-625 warn against. Also hardens against T-35-08
(`idp_sso_url` query collision: an operator-supplied SSO URL that already contains
`SAMLRequest=` or `Signature=` parameters silently changes the signed bytes after append)
and verifies T-35-09 (the `Destination` attribute on the AuthnRequest XML — ADFS rejects
signed requests without it per OASIS Bindings §3.4.5.2).

Output: `Relyra.start_login/3` (and `do_start_login/3`) extended to thread `:redirect_query`
into the return map for signed connections while preserving the existing `:redirect_params`
shape for unsigned connections; `LoginController.create/2` dispatches on the new key with a
new private `redirect_to_idp_signed/3` that appends bytes verbatim; a new typed error
`:invalid_idp_sso_url`; extended `test/relyra_test.exs` and `test/phoenix/login_controller_test.exs`
coverage; assertion (or addition if missing) that AuthnRequest XML emits the `Destination`
attribute.
</objective>
