<objective>
Add the persisted `signed_request_encoding` field to `Relyra.Ecto.Connection`, thread it
through `ConnectionSnapshot.base_runtime_attrs/1` to the runtime struct, mirror it on
`Relyra.Connection`, and create the corresponding `:string` Ecto migration. This is the
schema seam that surfaces the D-08/D-09 encoding option to adopters as a per-connection
admin-UI-settable field — the ADFS preset (Plan 04) sets it to `:adfs_lower`; all other
presets and existing connections leave it nil and the spec-correct `:rfc3986_upper`
default is applied at signing time inside `Binding.encode_redirect/3` (Plan 02).

Purpose: AUTHN-02 requires the encoding variant to be per-connection persistent (not
process-config or a runtime-only flag) so operators can flip ADFS-quirk handling per
trust relationship from the admin UI. Per CONTEXT.md D-14, the field lives top-level on
`Connection` (NOT in embedded `RuntimePolicy`) for direct DB queryability, mirroring the
`sign_authn_requests` placement convention established Phase 32 D-10/D-11.

Output: One new column (`:string`, nullable, no default) added via Ecto migration;
schema field declared as `Ecto.Enum` with values `[:rfc3986_upper, :adfs_lower]` casting
to/from that string column; both `draft_changeset/2` and `update_changeset/2` cast the
field; `ConnectionSnapshot.base_runtime_attrs/1` threads it via `Map.get/3` (nil safe);
`Relyra.Connection` runtime struct carries the field (default nil); two test files are
extended with cast + threading coverage.
</objective>
