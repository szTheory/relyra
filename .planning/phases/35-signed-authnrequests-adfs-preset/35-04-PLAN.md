<objective>
Ship the `Relyra.Provider.ADFS` provider preset and complete the established two-registration
pattern so DB-stored connections can carry `provider_preset: :adfs`.

This is a pure-data preset module (per D-15) with the locked default-config map; it carries
`sign_authn_requests: true` and `signed_request_encoding: :adfs_lower` so adopters who pick the
ADFS preset get the load-bearing ADFS-interop quirks (RSA-SHA256 + lowercase percent-encoding)
fail-closed by default. The cryptographic primitives that consume these flags ship in earlier
plans (Plan 01: `signing_digest_atom/1` + `sign_redirect_query/3`; Plan 02:
`Binding.encode_redirect/3` raw-DEFLATE + `:adfs_lower` post-process); Plan 03 adds the
`signed_request_encoding` field on `Relyra.Ecto.Connection` so the atom value flows through
cast → schema → runtime snapshot.

Purpose: Close AUTHN-04's preset half (the runbook half ships separately in a later plan). The
two-registration pattern (`@presets` map in `Relyra.Provider` + `@provider_presets` list in
`Relyra.Ecto.Connection`) is established (Phase 32 D-11); this plan extends both lists
additively without touching any other preset.

Output:
- `lib/relyra/provider/adfs.ex` — new module mirroring the `Relyra.Provider.Okta` / `Relyra.Provider.Entra` skeleton (six `@impl true` callbacks; `default_config/0` returns the locked D-15 map verbatim).
- `lib/relyra/provider.ex` `@presets` map gains the `adfs: Relyra.Provider.ADFS` entry.
- `lib/relyra/ecto/connection.ex` `@provider_presets` list gains `:adfs` (appended to preserve atom order for any non-set-based consumers).
- `test/provider/provider_test.exs` gains preset-registration + `default_config/0`-shape + `apply_defaults/2` + `translate_label/2` assertions.

Non-goals (do NOT do in this plan):
- Do NOT modify `Relyra.Provider.Okta` / `Provider.Entra` / `Provider.GoogleWorkspace`.
- Do NOT add a `Relyra.Provider.Ping` or `Relyra.Provider.OneLogin` module — the planning_context's mention of those is descriptive of "what the registry could one day hold"; they do not exist today and are out of Phase 35 scope.
- Do NOT write or modify `guides/recipes/adfs.md` — runbook ships in a later plan (AUTHN-04 docs half).
- Do NOT touch the `signed_request_encoding` Ecto.Enum schema field; Plan 03 owns that schema change. This plan's preset references the atom value `:adfs_lower` and assumes the cast list already accepts it.
- Do NOT modify any test under `test/security/`, `test/relyra/protocol/`, `test/relyra/security/`, or `test/conformance/` — Plans 01/02/06/07 own those.
