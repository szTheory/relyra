## User Constraints (from CONTEXT.md)

### Locked Decisions

- **D-01:** The setup journey must advertise metadata, ACS, and test-login URLs for the same enabled connection using the mounted `/saml/:connection_id/...` route family. The stale, unmounted `/auth/saml/metadata` and `/auth/saml/acs` values must not remain as operator configuration guidance.
- **D-02:** Deterministic integration evidence must prove that the endpoint values rendered by Setup resolve to the actual metadata, login, and ACS route contract. A string/suffix assertion against rendered HTML alone is insufficient because it allowed the existing route drift.
- **D-03:** Preserve fail-closed, runtime-supplied Basic Auth for `/login/admin` and the entire `/relyra/admin` mount, including validation traces. Do not introduce checked-in credentials, implicit usable defaults, a public trace bypass, or a route that establishes admin scope without authenticating through the existing host-owned boundary.
- **D-04:** Use an operator-chosen `DEMO_ADMIN_USERNAME` and `DEMO_ADMIN_PASSWORD` as an explicit, visible prerequisite before launching a journey that promises access to the operator trace. The Make-first launcher and evaluator documentation must explain the same credential handoff and the recovery path from a 401 challenge without printing or persisting secret values.
- **D-05:** Deterministic tests must cover both sides of the boundary: configured valid credentials reach the intended trace path, while missing, partial, and invalid credentials remain denied. The public Solo/FakeIdP and optional Fleet/Keycloak instructions must agree with the tested journey rather than relying on CI-only credential injection.

### the agent's Discretion

- Exact helper/module boundaries for deriving connection-scoped URLs, provided the displayed values and mounted routes share a drift-resistant contract.
- Exact placement and wording of credential setup instructions across `Makefile`, `.env.example`, and evaluator guides, provided credentials remain operator-chosen, runtime-only, and visible before the trace step.
- Exact split between LiveView, router/controller, and documentation drift tests, provided the evidence exercises routability and both authenticated and rejected admin paths.

## Summary

The closure should make the Setup LiveView derive one coherent metadata/login/ACS URL set from the selected enabled connection and Phoenix’s mounted `/saml/:connection_id/*` contract. The current LiveView hard-codes obsolete `/auth/saml/*` paths, while `mix phx.routes` confirms that only scoped `/saml/:connection_id/{metadata,login,acs}` routes exist. Put the derivation in one small private helper/assign boundary, render all three values from it, and redirect test login to the same derived local route. [VERIFIED: codebase grep + `mix phx.routes`; CITED: https://phoenix.hexdocs.pm/routing.html]

The second closure is a contract handoff, not a new auth system. `DemoAdminAuth` already rejects missing credentials with a Basic challenge and halts; existing controller tests prove absent, partial, invalid, and valid cases. The public launcher and guides must require operator-selected runtime environment values before any trace instruction, and base Solo Compose must forward those values just as proxy Compose already does. Tests must prove the configured credential reaches the trace and that every incomplete/invalid state stays challenged. [VERIFIED: codebase grep; CITED: https://plug.hexdocs.pm/Plug.BasicAuth.html]

**Primary recommendation:** Add a route-derived Setup URL helper plus a single explicit credential-preflight contract shared by base/proxy Compose, `make url`, `.env.example`, evaluator docs, and deterministic auth/route tests; do not add dependencies or touch Relyra library code. [VERIFIED: 72.1-CONTEXT.md + codebase grep]

### Pattern 1: Derive and render a complete connection-scoped URL set

**What:** Build metadata, login, and ACS values once from `connection.connection_id`, using verified local routes and the configured endpoint origin; assign the result to the socket and render assigns only. [CITED: https://phoenix.hexdocs.pm/routing.html]

**When to use:** Whenever a visible SAML setting represents one enabled connection. If there is no enabled connection, preserve a non-actionable empty/absence state rather than inventing an unscoped endpoint. [VERIFIED: SetupLive mount currently permits no connection]

**Example:**

```elixir
# Source pattern: Phoenix verified routes / URL generation
defp saml_urls(%{connection_id: connection_id}) do
  %{
    metadata: url(~p"/saml/#{connection_id}/metadata"),
    login: url(~p"/saml/#{connection_id}/login"),
    acs: url(~p"/saml/#{connection_id}/acs")
  }
end
```

### Pattern 2: Route-plus-behavior evidence

**What:** Assert the rendered values equal URLs derived from the seeded enabled connection, then exercise the corresponding router paths: metadata is a real GET, login follows the real redirect contract, and ACS is reached by the existing signed FakeIdP flow. [VERIFIED: fake_idp_flow_test.exs + router.ex]

**When to use:** Any UI that displays endpoints intended to be copied into an external IdP. A suffix assertion is not sufficient. [VERIFIED: D-02]

### Pattern 3: Explicit credential preflight without secret disclosure

**What:** Before printing a trace route or instructing the user to inspect it, require shell-provided `DEMO_ADMIN_USERNAME` and `DEMO_ADMIN_PASSWORD`; forward both to Solo and Fleet Compose, name variables/placeholders only, and explain that a 401 means values are missing or wrong. [VERIFIED: D-03..D-05 + existing proxy environment]

### Anti-Patterns to Avoid

- **Literal `/auth/saml/*` or unscoped `/saml/*` strings:** They are unmounted and can diverge from the router. Use one connection-derived helper. [VERIFIED: milestone audit + `mix phx.routes`]
- **Rendered-HTML-only endpoint tests:** They cannot prove dispatchability. Pair output assertions with metadata/login/ACS route behavior. [VERIFIED: D-02]
- **Default or generated public admin credentials:** They violate D-03/D-04 and undermine the fail-closed boundary. [VERIFIED: 72.1-CONTEXT.md]
- **Docs that say only “visit `/relyra/admin`”:** They promise a trace journey while omitting the Basic Auth prerequisite and recovery behavior. [VERIFIED: milestone audit + current guides]
- **Copying CI harness credential behavior into docs:** The Keycloak harness generates owned per-run values; public docs must instead use operator-selected runtime values and never print/persist them. [VERIFIED: test_keycloak_proxy_e2e.sh + D-05]

## Common Pitfalls

### Pitfall 1: Correct suffix, wrong mounted path

**What goes wrong:** A UI ends in `/metadata` or `/acs` but still points to a nonexistent route. [VERIFIED: milestone audit]

**How to avoid:** Use a single route-derived set and exercise each route contract in tests. [CITED: https://phoenix.hexdocs.pm/routing.html]

### Pitfall 2: Solo Compose does not receive the documented credentials

**What goes wrong:** Proxy Compose forwards `DEMO_ADMIN_*`, but base Solo Compose currently does not; operators can set variables yet still receive 401. [VERIFIED: docker-compose.yml + docker-compose.proxy.yml]

**How to avoid:** Put empty-default substitution in the base `demo_app.environment` too, leaving the proxy overlay consistent rather than authoritative. [VERIFIED: D-04 + current Compose split]

### Pitfall 3: Credential secret leaks through launcher/output/artifacts

**What goes wrong:** Echoing values, embedding examples, or retaining headers in browser artifacts makes the evaluator password repository-visible or durable. [VERIFIED: D-04 + test_keycloak_proxy_e2e.sh redaction policy]

**How to avoid:** Show variable names only, preserve runtime-only environment expansion, keep existing artifact redaction/disabled Playwright trace policy, and test wording/absence of literal secrets. [VERIFIED: D-04 + test_keycloak_proxy_e2e.sh]

### Pitfall 4: Authentication success is tested only in CI

**What goes wrong:** The Keycloak E2E script injects credentials, hiding that public Solo/Fleet instructions cannot complete the trace journey. [VERIFIED: milestone audit + test_keycloak_proxy_e2e.sh]

**How to avoid:** Add focused deterministic request tests for deny and valid trace access, then make launcher and both evaluator guides state the same preflight. [VERIFIED: D-05 + route_affordance_controller_test.exs]
