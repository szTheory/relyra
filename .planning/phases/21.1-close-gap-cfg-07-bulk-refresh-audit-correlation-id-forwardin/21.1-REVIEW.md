# Phase 21.1: Code Review Report

**Reviewed:** 2026-05-07
**Depth:** standard
**Files Reviewed:** 2
**Status:** issues_found

## Summary

The CFG-07 closure forwards `opts[:audit]` from `Relyra.Metadata.Refresh.refresh/2`
into `MetadataApply.apply_revision/4` and `MetadataApply.record_attempt/3` via a
new private `resolve_audit/1` helper. The success-path wiring is correct and the
bulk-refresh assertion in the new test suite genuinely exercises the gap closure:
without `audit:` forwarding, the bulk test's correlation-id assertion would fail.

However, the change has three quality defects worth surfacing:

1. The failure-path forwarding into `record_attempt/3` is a no-op because
   `record_attempt/3` does not consume `opts[:audit]` and does not write an
   audit row at all (only `apply_revision/4` calls `append_metadata_audit/6`).
   The third test ("D-35 single-audit-writer-seam invariant") therefore does not
   actually exercise the failure-path forwarding and only asserts an absence
   that is structurally guaranteed.
2. The `resolve_audit/1` "bulk path" branch lets explicit `nil` values in a
   caller-supplied audit map override the `actor`/`cause` defaults, which would
   produce an `AuditEvent` changeset validation failure (actor/cause are
   `validate_required` and `validate_length(min: 1)`).
3. The new test fixtures use 27-character connection IDs that violate the
   documented ULID-26 invariant (`Connection.@ulid_pattern`). The inserts
   succeed only because the test bypasses changesets via `@repo.insert!/1`.

No security vulnerabilities or correctness bugs in the success path. The
v0.5 milestone CFG-07 success-path closure is real; the failure-path claim is
not substantiated by the implementation or the test.

## Warnings

### WR-01: Failure-path `audit:` forwarding into `record_attempt/3` is a no-op

**File:** `lib/relyra/metadata/refresh.ex:100-127`

**Issue:** `record_refresh_failure/7` passes `audit: resolve_audit(opts)` to
`MetadataApply.record_attempt/3`, but `record_attempt/3`
(`lib/relyra/ecto/metadata_apply.ex:74-97`) does not read `opts[:audit]` and
never calls `AuditWriter.append_event/2`. It only inserts a `MetadataRevision`
row. Consequently:

- The phase comment ("D-21.1-03 fallback ordering ... closes the Phase 20
  batch-cohesion gap (CFG-07) without changing the apply_revision contract")
  overstates the change: the failure path does not produce a correlated audit
  row at all because no audit row is produced.
- The third test in the new suite ("[CFG-07] bulk refresh with one
  parse-failure produces NO :metadata, :applied row for the failing
  connection") asserts an absence (`length(applied) == 1`) that holds even
  with `audit:` removed from `record_refresh_failure/7`. It does not regression-guard
  the failure-path forwarding.

This is a correctness concern in the *plan-vs-code* sense: the audit gap
described as "CFG-07 closure" is half-closed. Either:
- Update `record_attempt/3` to also write an `:metadata, :attempted` (or
  similarly classified) audit row keyed by `audit[:correlation_id]`, OR
- Remove `audit: resolve_audit(opts)` from `record_refresh_failure/7` and the
  associated comment claim, and explicitly scope this phase to the success
  path only.

**Fix (option A — preserve current scope, remove dead forwarding):**
```elixir
defp record_refresh_failure(connection, source, repo, xml, error, outcome, opts) do
  _ =
    MetadataApply.record_attempt(
      connection.connection_id,
      %{
        metadata_source_id: source.id,
        # ...
        trust_summary: %{status: "failed", error_code: error.type}
      },
      repo: repo
      # `audit:` removed — record_attempt/3 does not consume it.
    )
  # ...
end
```

**Fix (option B — actually close the failure-path gap):** thread `audit_context(opts, ...)`
through `record_attempt/3` and append an audit row in that path. This is a
larger change and likely belongs in a separate phase.

### WR-02: `resolve_audit/1` lets explicit nil values defeat defaults in the bulk-path branch

**File:** `lib/relyra/metadata/refresh.ex:208-228`

**Issue:** In the `%{} = audit_map ->` branch:

```elixir
Map.merge(
  %{actor: "unknown", cause: "manual refresh"},
  audit_map
)
```

`Map.merge/2` keys-on-presence, not on non-nil. A caller passing
`audit: %{actor: nil, cause: "x", correlation_id: "..."}` produces
`%{actor: nil, cause: "x", correlation_id: "..."}`. That map flows into
`audit_context/2` (returns it as-is), then `append_metadata_audit/6` writes
`actor: nil` into the AuditWriter changeset, which fails
`validate_required([..., :actor, :cause])` and `validate_length(:actor, min: 1)`
(`lib/relyra/ecto/audit_event.ex:54-76`). Inside the `apply_revision` transaction
this triggers a rollback via `{:error, %Error{}}`, surfacing as a refresh
failure instead of a clean default-fallback.

In practice today, BulkActions and AutoRefresh both populate `actor`/`cause` as
non-empty strings, so the bug is latent. But the helper is documented as
producing "a valid audit row" from a partial map — and a partial map containing
explicit `nil` is the realistic shape of "partial."

**Fix:**
```elixir
defp resolve_audit(opts) do
  case Keyword.get(opts, :audit) do
    %{} = audit_map ->
      audit_map
      |> Enum.reject(fn {_k, v} -> is_nil(v) end)
      |> Map.new()
      |> then(&Map.merge(%{actor: "unknown", cause: "manual refresh"}, &1))

    _ ->
      %{
        actor: Keyword.get(opts, :actor) || "unknown",
        cause: Keyword.get(opts, :cause) || "manual refresh",
        correlation_id: nil
      }
  end
end
```

(The `||` rewrite in the second branch is a free improvement: today
`Keyword.get(opts, :actor, "unknown")` returns `nil` if the caller passes
`actor: nil` explicitly, with the same downstream consequence.)

### WR-03: Test fixture violates the ULID-26 connection-id invariant

**File:** `test/relyra/metadata/refresh_bulk_audit_test.exs:20-23, 75, 102-103`

**Issue:** `insert_enabled_connection!/1` is called with 27-character strings
(e.g., `"01JT74Q2YJ9WFM0MMSYF6QK4M1A"` — the documented ULID is 26 characters,
enforced by `Relyra.Ecto.Connection.@ulid_length` /
`@ulid_pattern = ~r/^[0-9A-HJKMNP-TV-Z]{26}$/`). The inserts succeed because
the helper bypasses the changeset and writes a raw `%Connection{}` via
`@repo.insert!/1`, so neither `validate_format` nor `validate_length` fires;
the database column has no length constraint either.

The pre-existing `test/relyra/metadata_refresh_test.exs` uses 26-character IDs
(`"01JT74Q2YJ9WFM0MMSYF6QK4M1"`). The new test added a trailing letter to
disambiguate three connections, exceeding the schema invariant.

This is not a test-runtime bug, but it sets a precedent that drifts from the
documented schema and will mask any future migration that adds a `CHECK
(length(connection_id) = 26)` constraint.

**Fix:** Use unique 26-char ULID-shaped IDs:
```elixir
# bulk test
for i <- 1..3, do: insert_enabled_connection!("01JT74Q2YJ9WFM0MMSYF6QK#{i}MN")
# 26 chars: 01JT74Q2YJ9WFM0MMSYF6QK1MN, etc.

# single-connection test
insert_enabled_connection!("01JT74Q2YJ9WFM0MMSYF6QK9BN")

# failure-path test
good = insert_enabled_connection!("01JT74Q2YJ9WFM0MMSYF6QK9CN")
bad  = insert_enabled_connection!("01JT74Q2YJ9WFM0MMSYF6QK9DN")
```

(Or simply call `Connection.generate_ulid/0` if exposed in test support.)

## Info

### IN-01: Failure-path test name oversells what it asserts

**File:** `test/relyra/metadata/refresh_bulk_audit_test.exs:100-153`

**Issue:** The describe block is "failure path — D-35 single-audit-writer-seam
invariant" and the test name advertises checking that the failing connection
produces no `:metadata, :applied` row. But D-35 is a much broader invariant
(only one writer for audit rows). The actual assertions reduce to: success
applies, failure doesn't apply, failure leaves a non-:applied
`MetadataRevision` row. None of those exercise the new `audit:` forwarding in
`record_refresh_failure/7` — they would all pass with that line removed
(see WR-01).

**Fix:** Rename to something like `"bulk refresh with one parse-failure
produces exactly one :metadata, :applied audit row sharing the bulk
correlation_id"` and drop the D-35 reference unless a separate test
specifically asserts the single-writer property.

### IN-02: `resolve_audit/1` doctring/comment overstates "always returns ... correlation_id"

**File:** `lib/relyra/metadata/refresh.ex:204-207`

**Issue:** The block comment claims "Always returns a map carrying actor,
cause, and correlation_id (nil when not provided by an upstream batch)." But
the `%{} = audit_map ->` branch returns `Map.merge(defaults, audit_map)` where
`defaults` is `%{actor: "unknown", cause: "manual refresh"}` — no
`correlation_id` key. If a caller passes `audit: %{actor: "x", cause: "y"}`
(no correlation_id), the returned map has no `:correlation_id` key.

In practice the downstream `Map.get(audit, :correlation_id)` in
`append_metadata_audit/6` (`metadata_apply.ex:901`) treats absent and `nil`
identically, so there is no behavioral bug. But the comment is incorrect.

**Fix:** Either add `correlation_id: nil` to the defaults map, or correct the
comment to "Returns a map carrying at least actor and cause."

### IN-03: `failure_outcome/1` clauses can collapse to one head with a guard

**File:** `lib/relyra/metadata/refresh.ex:192-194`

**Issue:** Pre-existing minor duplication; not introduced by this phase but

```elixir
defp failure_outcome(%Error{type: :malformed_xml}), do: :parse_failed
```

```elixir
defp failure_outcome(%Error{type: type}) when type in [:malformed_xml, :metadata_wrong_root],

defp failure_outcome(%Error{}), do: :validation_failed
```

### IN-04: Trailing single-line `details =` rebind is dead

**File:** `lib/relyra/metadata/refresh.ex:230-236`

**Issue:** Pre-existing, not introduced by this phase:
```elixir
defp failure_details(xml, error) do
  details =
    %{error_code: error.type}
    |> maybe_put(:xml_bytes, is_binary(xml), if(is_binary(xml), do: byte_size(xml), else: nil))

  details
end
```
The named binding adds no value over returning the pipeline directly.
**Fix:**
```elixir
defp failure_details(xml, error) do
  %{error_code: error.type}
  |> maybe_put(:xml_bytes, is_binary(xml), if(is_binary(xml), do: byte_size(xml), else: nil))
end
```
