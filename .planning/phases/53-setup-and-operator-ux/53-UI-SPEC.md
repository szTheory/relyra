# Phase 53 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none |
| Preset | not applicable |
| Component library | Phoenix LiveView function components; no shadcn/radix/base-ui |
| Icon library | none; use text links/buttons and unicode symbols for checklist state (e.g., ✓, ◯) |
| Font | Helvetica, Arial, sans-serif |

Source: `.planning/REQUIREMENTS.md` UX-01; `.planning/phases/53-setup-and-operator-ux/53-CONTEXT.md`; inherited from Phase 51.

Contract:
- Build `LedgerLoopWeb.SetupLive` using Phoenix LiveView for the nonlinear setup checklist (Decision D-01).
- No external frontend frameworks (Tailwind, React, etc.). Retain plain Phoenix templates and app-local CSS.
- UX must follow Relyra's calm/operator brand.
- Admin views must mock a host admin session (inject `"admin_actor"` into Plug session) to allow viewing mounted operator UI (Decision D-02).
- Support links must deep-link directly to `/relyra/admin/connections/:id/trace` (Decision D-03).
- Receipts strictly render redacted summary data, never raw protocol artifacts (Decision D-04).

## Spacing Scale

Declared values (must be multiples of 4, inherited from Phase 51):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Inline metadata gaps, badge inner offsets |
| sm | 8px | Compact label/value spacing, checklist item padding |
| md | 16px | Default element spacing, card padding, form row spacing |
| lg | 24px | Page padding, section gaps, setup header margin |
| xl | 32px | Empty state padding, major panel spacing, receipt boundaries |
| 2xl | 48px | Page vertical rhythm on desktop |
| 3xl | 64px | Full-page flow vertical spacing |

Exceptions:
- Interactive controls must have a minimum target size of 44px by 44px when rendered as standalone buttons or nav items.

## Typography

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 16px | 400 | 1.5 |
| Label | 14px | 400 | 1.4 |
| Heading | 20px | 600 | 1.2 |
| Display | 28px | 600 | 1.2 |

Contract:
- Maintain exactly these four text sizes.
- Maintain only 400 and 600 weights.
- Checklist item headers use Heading (20px). Checklist descriptions use Body (16px).
- Metadata key/value pairs in receipts use Label (14px).
- Status indicators and microcopy use accessible text over color-only cues.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | #ffffff | Page background, receipt panels, checklist body |
| Secondary (30%) | #f0f4f8 | Header band, setup navigation strip, completed checklist item background |
| Accent (10%) | #0066cc | Primary CTA (e.g., "Start Test Login", "Enable Connection"), active text links |
| Destructive | #c62828 | Typed rejection/error state, destructive actions (e.g., "Delete Draft") |

Semantic support colors (Inherited from Phase 51):
- Success: #2e7d32 for enabled/verified state labels and completed checklist items.
- Warning: #b87600 on #fff7e6 for draft, missing metadata, or setup-incomplete labels.
- Neutral text: #555555 for supporting copy, receipt metadata keys; #333333 for primary text.
- Borders: #d1d9e1 for panels, checklist boundaries, receipt outlines.

Contract:
- Status indicators MUST include text (e.g., "Verified", "Draft", "Missing Metadata", "Failed"). Color alone is never sufficient.
- Support light/dark/system theming gracefully if base CSS variables are implemented, otherwise rely on light-mode foundations.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA | Start Test Login / Enable Connection |
| Empty state (Setup) | No IdP metadata provided. |
| Error state (Trace) | Login failed. View detailed trace evidence below. |
| Destructive action | Delete Draft Connection. This will permanently remove the setup progress. Continue? |
| Setup Checklist Step 1 | SP Settings (Copy Relyra configuration to your IdP) |
| Setup Checklist Step 2 | IdP Metadata (Provide XML or URLs from your IdP) |
| Setup Checklist Step 3 | Attribute Mapping (Preview how SAML attributes map to LedgerLoop users) |
| Setup Checklist Step 4 | Test & Enable (Perform a test login to verify the trust path) |

Receipt Copy Rules (Requirement FLOW-03, Decision D-04):
- Say exactly what was verified: "SAML Signature Verified", "Principal Extracted", "Replay Checked".
- Say what was mapped: "SAML Identity mapped to LedgerLoop User".
- Never expose raw XML, PEM blocks, or secrets in the receipt UI.
- Use explicit boundary language: "Relyra verified SAML trust", "LedgerLoop established session".

## Interaction Contract

Setup Checklist Layout (`LedgerLoopWeb.SetupLive`):
- Nonlinear task-list pattern: User can click into any step. Steps clearly indicate status (e.g., Not Started, In Progress, Complete).
- SP Settings panel: Provides copyable text fields for ACS URL, Entity ID, etc. Includes a "Copy to clipboard" affordance.
- IdP Metadata panel: Offers a form to paste XML or input a metadata URL.
- Mapping Preview panel: Displays a read-only table mapping standard Relyra attributes to LedgerLoop expected schemas.
- Test & Enable panel: Contains the "Start Test Login" button. Displays the enablement receipt upon success.

Receipts Layout:
- Rendered as bounded panels with `#d1d9e1` borders.
- Structured as key-value pairs (Label/Value) using the Typography scale.
- Clear separation between Relyra verification output and LedgerLoop host actions.

Operator Admin & Support Trace Hand-off (Decisions D-02, D-03):
- A "Mock Admin Login" button or plug injects `"admin_actor"` to reveal admin paths.
- Support scenarios list simulated failures. Clicking a scenario links directly to `/relyra/admin/connections/:id/trace`.
- Trace view must remain strictly within mounted `Relyra.LiveAdmin`, not duplicated in LedgerLoop.

Accessibility (UX-01):
- Checklist items must be keyboard navigable.
- Copy-to-clipboard actions must announce success to screen readers (e.g., ARIA live region).
- Focus states clearly indicated (accent color outline).
