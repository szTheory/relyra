<task type="auto" tdd="true">
  <name>Task 1: Logout Bindings Parser</name>
  <files>lib/relyra/protocol/binding.ex, test/relyra/protocol/binding_test.exs</files>
  <behavior>
    The bindings must parse redirect bindings (which use deflate + base64 + url encode) and handle the param difference between SAMLRequest vs SAMLResponse.
    
    Cases:
    - `decode_redirect/2` with valid SAMLRequest query param -> Returns `{:ok, %{response_xml: xml, relay_state: rs}}`.
    - `decode_redirect/2` with valid SAMLResponse query param -> Returns `{:ok, %{response_xml: xml, relay_state: rs}}`.
    - `decode_redirect/2` missing both -> Returns `{:error, error}`.
    - `encode_redirect/3` with type `:response` -> Returns map with `"SAMLResponse" => ...`.
  </behavior>
  <action>
    Update `encode_redirect/3` to accept an `opts` keyword list or type param to determine if it should output `SAMLRequest` or `SAMLResponse`.
    Implement `decode_redirect(params, opts \\ [])` which reads either `SAMLRequest` or `SAMLResponse` from params.
    Deflate decompression might be needed if SAML standard HTTP-Redirect binding uses it (often it does: `zlib:inflate`). The current `encode_redirect` does not do DEFLATE, so `decode_redirect` should just undo `encode_redirect` (base64 decode).
    Add Telemetry spans for `decode_redirect` mirroring `decode_post`.
  </action>
  <verify>
    <automated>mix test test/relyra/protocol/binding_test.exs --warnings-as-errors</automated>
  </verify>
  <done>HTTP-Redirect and HTTP-POST incoming SAML messages can be properly decoded.</done>
