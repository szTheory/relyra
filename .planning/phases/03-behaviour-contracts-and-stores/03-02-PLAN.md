<objective>
Implement concrete request/replay store adapters with atomic one-time semantics: ETS defaults for dev/test with loud production warnings, and optional Ecto adapters for production-safe concurrency guarantees without hard-coupling protocol core to Ecto.
</objective>

<threat_model>
  <threat id="TM-03-02-REPLAY-RACE-BYPASS" severity="high">
    Non-atomic replay/request consume operations allow concurrent duplicate assertion acceptance, violating replay protection and creating account takeover risk.
  </threat>
  <threat id="TM-03-02-OPTIONAL-DEP-COUPLING" severity="medium">
    Ecto adapter code that compiles unguarded can break base-library builds when optional dependencies are absent.
  </threat>
  <threat id="TM-03-02-ETS-PROD-MISUSE" severity="medium">
    Silent ETS usage in production can create false confidence about durability and cross-node replay guarantees.
  </threat>
  <mitigations>
    - Implement ETS adapters with atomic primitives (`:ets.insert_new/2`, `:ets.take/2`, and conditional matching for request-id consume checks).
    - Implement Ecto adapters using conflict-safe insert/update semantics and return typed `%Relyra.Error{}` atoms (`:replayed_assertion`, `:request_intent_not_found`, `:request_intent_consumed`).
    - Guard Ecto code paths with runtime dependency checks (`Code.ensure_loaded?(Ecto.Repo)` and adapter-level guard functions) so base compile succeeds without optional deps.
    - Emit explicit runtime warnings when a runtime-safe production flag is enabled (adapter option or `Application` env), including "single-node only" and "non-durable" language, without calling `Mix` in runtime paths.
    - High-severity threats are blocking under ASVS L1 policy; do not mark this plan complete unless all verification commands pass.
  </mitigations>
  <verification_commands>
