<objective>
Freeze the Phase 3 extension API by publishing the five public behaviours as the stable contract surface and adding internal default adapter scaffolding that stays private (`@moduledoc false`) and fail-closed until concrete ETS/Ecto adapters land.
</objective>

<threat_model>
  <threat id="TM-03-01-CONTRACT-DRIFT-FAIL-OPEN" severity="high">
    Unstable or underspecified behaviour callbacks allow adapters to return non-typed values, which can silently bypass request-intent or replay enforcement in downstream phases.
  </threat>
  <threat id="TM-03-01-DEFAULT-ADAPTER-API-LEAK" severity="medium">
    Publishing default adapter internals as public API creates long-term compatibility lock-in and encourages direct coupling to non-production implementations.
  </threat>
  <mitigations>
    - Create exactly five public behaviour modules (`ConnectionResolver`, `SessionAdapter`, `UserMapper`, `RequestStore`, `ReplayStore`) with explicit callback names, arities, and `%Relyra.Error{}` typed returns.
    - Keep default adapter implementations internal via `@moduledoc false` and return typed `:adapter_not_configured` / `:unsupported_default_adapter` errors when no runtime adapter is configured.
    - Add seam-contract tests that assert callback presence/arity and public tuple/error contracts.
    - High-severity threats are blocking under ASVS L1 policy; do not mark this plan complete unless all verification commands pass.
  </mitigations>
  <verification_commands>
    - `rg -n "defmodule Relyra\\.(ConnectionResolver|SessionAdapter|UserMapper|RequestStore|ReplayStore)|@callback" lib/relyra/*.ex`
    - `rg -n "put_intent\\(relay_state, intent, opts \\\\ \\[\\]\\)|fetch_intent\\(relay_state, opts \\\\ \\[\\]\\)|consume_intent\\(relay_state, request_id, opts \\\\ \\[\\]\\)" lib/relyra/request_store.ex`
    - `rg -n "consume_replay_key\\(replay_key, metadata, opts \\\\ \\[\\]\\)|@moduledoc false" lib/relyra/replay_store*.ex lib/relyra/replay_store/**/*.ex`
    - `mix test test/security/extensions/seam_contract_test.exs --warnings-as-errors`
    - `mix test test/relyra_test.exs --warnings-as-errors`
  </verification_commands>
</threat_model>

  - Every behaviour callback returns strict typed tuples with `%Relyra.Error{}` on failure; no bare `:error` or untyped exceptions are part of the contract.

  - Callback names/arity are locked by seam-contract tests to prevent Phase 4 runtime churn.
