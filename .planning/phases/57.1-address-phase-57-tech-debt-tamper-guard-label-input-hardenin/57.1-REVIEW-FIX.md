## Fixed Issues

### WR-01: `extract_in_response_to/1` grabs the first `ID=` attribute anywhere in the document, not the root element's

**Files modified:** `demo/ledger_loop/lib/ledger_loop_web/controllers/fake_idp_controller.ex`
**Commit:** 5f965cf
**Applied fix:** Anchored the ID-capture regex to the document's first start tag
(the root AuthnRequest element) by replacing `~r/\bID="([A-Za-z_][A-Za-z0-9._-]*)"/`
with `~r/\A\s*<[^>]*\bID="([A-Za-z_][A-Za-z0-9._-]*)"/`. This makes the code's
behavior match its stated contract ("root @ID") so a crafted SAMLRequest cannot
thread a non-root `ID` (e.g. `<Issuer ID="x">`) into `InResponseTo`. Updated the
inline comment to describe the anchored behavior. The NCName constraint and
downstream escaping are unchanged.

**Verification note:** This fix changes regex matching semantics. Tier 1 (re-read)
and Tier 2 (parse-check + `mix format` via pre-commit hook) passed, but the new
anchor (`\A\s*<[^>]*`) should be confirmed by a human against the SP AuthnRequest
fixtures used in the controller test to ensure the root-element `ID` is still
captured for the normal SP-initiated path.

### WR-02: Tamper regex capture group is dead; replacement does not preserve `Format` attribute

**Files modified:** `demo/ledger_loop/lib/ledger_loop/fake_idp/signer.ex`
**Commit:** fbb4aa0
**Applied fix:** Rewrote the tamper replacement to preserve the original `<NameID>`
open and close tags using back-references: `String.replace(xml,
~r/(<NameID[^>]*>)[^<]+(<\/NameID>)/, "\\1TAMPERED\\2")`. Only the text node is
mutated now, so any `Format` attribute survives — keeping the digest-mismatch
rejection at the crypto gate (`do_verify/4`) rather than shifting it to an earlier
protocol step if the template ever emits `<NameID Format="...">`. The no-op guard
(`if tampered == xml`) is retained.

**Verification note:** This fix changes regex replacement semantics. Tier 1 and
Tier 2 passed. A human should confirm the back-referenced replacement still
produces a digest mismatch (not merely a structural no-op) against the current
bare-`<NameID>` template in the `signer_test.exs` tamper test.

### WR-03: `signed_response/1` emits `InResponseTo=""` when caller passes `nil`, which a strict SP would reject

**Files modified:** `demo/ledger_loop/lib/ledger_loop/fake_idp/signer.ex`
**Commit:** 0639577
**Applied fix:** `response_xml/3` now builds the `InResponseTo` attribute
conditionally — emitting nothing when `fields.in_response_to` is `nil` or `""`, and
` InResponseTo="..."` (with `AttributeEscape.escape_attribute/1`) otherwise.
Direct, non-SP-initiated visits no longer produce a `InResponseTo=""` that a strict
SP could reject as a malformed correlation. Because `response_xml/3` is the single
interpolation site called identically across all three signing passes
(placeholder/digest/signed), the conditional attribute remains digest-stable.
