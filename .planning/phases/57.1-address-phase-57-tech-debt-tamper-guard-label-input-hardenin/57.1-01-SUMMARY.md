## Accomplishments

- WR-05: `tamper/1` now raises `"tamper/1 failed to locate <NameID>; template drifted"` when the regex finds no `<NameID>` to replace, preventing silent false-negative rejection proofs; regex broadened to `<NameID[^>]*>` to future-proof against `Format=` attribute variants
- WR-01: `response_xml/3` escapes all interpolated attribute values via `Relyra.Security.XML.AttributeEscape.escape_attribute/1` and all element-text values via a new private `xml_text/1` helper — escaping lives inside the single template function so all three passes (placeholder/digest/signed at lines 65/77/83) escape identically, keeping the digest stable; `in_response_to: "a<b>&c"` no longer crashes the signer's own re-parse
- IN-02: `keypair.ex` replaces bare `[entry] = :public_key.pem_decode(pem_bin)` MatchError with a typed `case` matching `{:RSAPrivateKey, _der, :not_encrypted}` and a descriptive raise naming `@key_path` and the found entry tags; logic extracted to public `decode_pem_key/1` for testability

## Decisions Made

- **Expose `decode_pem_key/1` as public** rather than keeping `load_private_key/0` private: allows the adversarial test to feed a multi-entry PEM without writing a bad file to disk and without coupling to module-internal state. Low surface risk — the function is a diagnostic helper, not a security boundary.
- **`xml_text/1` private helper** rather than reusing `AttributeEscape.escape_attribute/1` for element text: `AttributeEscape` escapes tab/newline/CR and does not escape `>`, which is wrong for element-text nodes. The four-line helper is the correct minimal solution.
- **Broadened tamper regex** to `<NameID[^>]*>` without broadening the replacement `<NameID>TAMPERED</NameID>` — follows RESEARCH Pitfall 3 precisely to avoid false-positive guard trips on today's template.
