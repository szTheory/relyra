# Phase 83 Plan: Mutation testing of the security core

Measure whether the security-core TESTS actually detect broken checks, and
close the real gaps to a score plateau.

## Approach

- Add `{:mutare, "0.5.1", only: [:dev, :test], runtime: false}` + `.mutare.exs`
  scoping mutation to the pure trust core (signature, signed-node, algorithm
  policy, the XML seam, validation pipeline, logout validator, metadata parser).
- Baseline spike: mutare's sandbox is a git-LESS copy, so a few governance/
  adoption meta-suites fail there. Gate them behind `RELYRA_MUTATION_SUITE` in
  `test_helper.exs` (`:non_hermetic_sandbox` tag) so the mutation baseline is
  hermetic; they still run in every ordinary lane.
- `mutation.yml`: scheduled + dispatch, `mix mutare --report json:mutare.json`,
  uploads the score artifact, outside ci-gate.
- `mutation_lane_test.exs`: pin the lane (mutare exact, fresh-process-per-mutant,
  absent from ci-gate) + the anti-weakening guard on the permanent corpora. Its
  own gated `cmd mix test` line.
- Run rounds on the security-critical `algorithm_policy.ex`; kill real gaps with
  sharper tests, mark equivalents with `mutare:ignore`, record the trend.

## Verification

`mix qa`, `mix ci.security`, `mix format --check-formatted` exit 0; the mutation
lane runs as its own gated process; actionlint passes the new workflow; the score
trend is recorded in the SUMMARY round log.
