### BLOCKER: INT-01 — bulk refresh drops correlation_id and operator actor

`lib/relyra/ecto/bulk_actions.ex:16-18` correctly seeds `opts[:audit][:correlation_id]` per bulk run.
`lib/relyra/metadata/refresh.ex:52-65` calls `MetadataApply.apply_revision(..., repo: repo)` but does **not** forward `opts[:audit]` into `apply_revision` opts. Inside `apply_revision`, `audit_context(opts, revision_attrs)` (`metadata_apply.ex:933-944`) finds `opts[:audit] == nil` and falls through to `audit_context_from_revision/1`, which resolves `correlation_id: Map.get(revision_like, :correlation_id)` to `nil`.

**Net effect:** A bulk "Refresh Metadata" over N connections produces N audit rows with **`correlation_id = nil`, `actor = "unknown"`, `cause = "manual refresh"`** — silently violating the Phase 20 batch-cohesion invariant (one shared correlation per bulk run) and losing operator identity.

**Asymmetric:** Bulk `:enable` / `:disable` work correctly because `Connections.enable/2` accepts `audit:` directly. Only `:refresh_metadata` regresses because `Refresh.refresh/2` predates the bulk-audit contract.

**Fix:** Localized; have `Refresh.refresh/2` forward `audit:` into `apply_revision` opts (or merge `correlation_id` into `revision_attrs`). No schema impact.
